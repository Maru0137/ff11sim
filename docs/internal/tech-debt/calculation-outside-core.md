# ステータス計算の一部が library crate のコアの外にある

[ADR 0001](../adr/0001-rust-wasm-static-site.md) は、計算とゲーム仕様のモデリングを `rust/src/` の
library crate（コア）に置き、`rust/src/wasm.rs` のアダプタは型変換と serde シリアライズに徹して計算ロジックを
持たない、と決めている。実際には、ステータスの計算の一部がアダプタ層と Web 側にある。この文書はその食い違いを
記録する。仕様書 [0007 ステータスの計算](../specs/0007-status-calculation.md) の設計上の論点 D1 から参照される。

## コアの外にある計算

2026-10-18 にコードを読んで確かめた範囲。

| 場所 | 持っている計算 |
|---|---|
| `rust/src/wasm.rs:599`（`combat_skills`） | 有効スキル値の解決（スキル上限で抑えた値に、全スロット共通のスキルボーナスとスロットごとのスキルボーナスを足す）と、メイン・サブ・レンジの武器のスキル値の解決 |
| `rust/src/wasm.rs:671`（`chara_to_status_result`） | ステータスの集計（ジョブ特性・ギフト・ジョブポイントのカテゴリ効果の合算）と、ギフトのスキルボーナスの加算 |
| `web/src/status/compute.ts:328-370` | 装備から拾った値とキャラクター由来の値を足す合成値（トゥルーショット・リサイクル・ダブルショット・トリプルショット・コンサーブMP の合計、実効魔命） |

## なぜ負債か

- ネイティブ（rlib）の入口（`rust/src/main.rs` の CLI、`rust/examples/`）からは、アダプタ層と Web 側の計算を
  呼べない。同じキャラクターでも、ブラウザとネイティブで求まる値の範囲が違う。
- 計算の規則を変えるとき、コア・アダプタ・Web の 3 か所を見る必要がある。仕様書 0007 の 2026-10-18 の改訂
  （スキル上限とメリットポイントの扱い、スロット専用のスキルボーナスの範囲）は、`rust/src/skills.rs`・
  `rust/src/equip.rs`・`rust/src/wasm.rs` にまたがる。

## 方針

ADR 0001 は緩めず、これらの計算をコア（`rust/src/chara.rs` など）へ移し、`wasm.rs` を型変換だけにする。振る舞いは
変えない（リファクタリング）。移す範囲と時期は GitHub issue #65 で決める。

## 経緯

2026-10-12 の仕様書 0007 の grill で見つかり、ADR を緩めずにコアへ移すと決めた（0007-Q5）。2026-10-18 の
リファインメント R1（指摘 R1-O7）で、この文書がまだ無いことが分かり、作った。
