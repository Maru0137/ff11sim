# 装備検索

この仕様書の用語は [用語集](../../../CONTEXT.md) と、依存する仕様書（[0004 装備の解釈](0004-equip-interpretation.md)、[0003 ステータスビューの管理](0003-status-view-management.md)）の用語節に従う。この仕様書で定義する語は「用語」節に書く。

## 用語

**装備検索画面**:
アイテムデータからアイテムを探す画面。URL は `#/search`。

**検索条件**:
1 回の検索に使う条件の全体。キーワード・スロット・ジョブ・iLv119 絞り込み・フィルター行・ソート基準・昇順か降順か・ステータス名、の組。

**キーワード**:
アイテムの名前で探すために、利用者が検索欄に入れる文字列。
UI 上の検索欄のプレースホルダーは「装備名で検索...」。

**アイテム項目**:
アイテムデータで 1 つのアイテムが持つ値の欄（ID・英語名・Lv・ダメージ・装備可能ジョブなど）。
用語集のプロパティ（キャラクター（→ 0002）と装備セット（→ 0006）から求まる値）とは別物である。
_使わない_: プロパティ（この意味で）

**フィルター行**:
アイテム項目・演算子・値の 3 つ組で書く絞り込みの条件 1 件。利用者が何行でも足せる。値は、アイテム項目によって入力欄に入れるか選択欄で選ぶ（AC18）。

**スロット区分**:
結果表のスロット列と、スロットの選択欄で使う 14 個の区分。メイン・サブ・レンジ・矢弾・頭・胴・両手・両脚・両足・首・腰・耳・指・背 で、この順に並べる。「耳」は左耳と右耳、「指」は左指と右指をまとめたもので、それ以外は用語集のスロットの表示名と同じである。
_使わない_: 表示名（この意味で）

**iLv119 絞り込み**:
メイン・サブ・レンジ・頭・胴・両手・両脚・両足 の 8 スロットのどれかに着けられるアイテムを、アイテムレベル（iLv）が 119 のものだけに絞る条件。どのスロットの選択で使えるかと、「全スロット」のときの扱いは受け入れ基準 AC14〜AC16 にある。
UI 上の表示は「iLv119のみ」。

**優先並び**:
ソート基準より先に必ず適用される並べ替えの規則。名前末尾の「+数字」が大きいアイテムを先にする（AC27 の 1）。
利用者は切り替えられない。

**説明文ステータスソート**:
利用者が入れたステータス名を手がかりに日本語のアイテム説明文から数値を 1 つ読み、その数値で並べるソート基準。
UI 上の表示は「説明文ステータス」。

**ソート基準**:
結果の並べ替えに使う規則として、利用者が選ぶもの 1 つ。選択肢は AC25 にある。優先並びの後に適用する（AC27）。

**ステータス名**:
説明文ステータスソートで、アイテム説明文から値を読む効果の名前として、利用者がステータス名の欄に入れる文字列（例: STR、攻）。用語集のステータス（プロパティの値の全体）とは別物である。

**ページ**:
検索結果を 50 件ずつに区切った 1 区切り。画面には 1 ページずつ表示する。

## 課題

- **P1**: 利用者は、ある装備の装備可能ジョブ・スロット・Lv・説明文をゲームの外で確かめたいが、名前の表記（カタカナとひらがな、全角と半角、日本語名と英語名）が分からないと 1 万件を超えるアイテムデータから目当てのアイテムを見つけられない。
- **P2**: 装備を選ぶ利用者は、あるスロット・ジョブで使えるアイテムを、Lv や特定の効果の大きさで比べたいが、候補を手で集めて並べるのは手間がかかる。

## ユーザーストーリー

- **S1**: 利用者として、名前の一部をひらがな・カタカナ・英語のどれで入れてもアイテムを見つけたい（→ P1）
- **S2**: 利用者として、スロット・ジョブ・iLv119 で候補を絞りたい（→ P2）
- **S3**: 利用者として、Lv・ダメージ・隔・装備可能種族などのアイテム項目の条件を重ねて、候補をさらに絞りたい（→ P2）
- **S4**: 利用者として、候補を名前・Lv・iLv・カテゴリ・説明文の中の特定のステータスの値で並べ替えたい（→ P2）
- **S5**: 利用者として、50 件を超える結果を順に送って全部見たい（→ P1, P2）
- **S6**: 利用者として、同じ装備の強化段階（名前末尾の「+数字」）違いは、どのソート基準でも強化段階の高いものを先に見たい。強化段階の高いものを先に見たり優先して選んだりすることが多いため（→ P2）

## ユーザージャーニー

### 全体の流れ

1. 利用者はサイドバーから装備検索画面を開くか、`#/search`（検索条件を載せた `#/search?...` を含む）または旧 URL の `search.html` を直接開く。
2. 画面は、URL に検索条件があればその検索条件で、無ければ既定の検索条件で検索した 1 ページ目を表示する。
3. 利用者は J1〜J4 の操作を任意の順で繰り返して検索条件を変え、結果を見る。結果が 50 件を超えれば J5 でページを送る。
4. 利用者が別の画面へ移って戻ってきても、検索条件と結果はそのまま残っている。検索のたびに URL は検索条件を載せたものに置き換わるので、利用者がブラウザでアプリを再読み込みすると、同じ検索条件の 1 ページ目に戻る。

### J1: 名前で探す（→ S1）

1. 利用者は検索欄にキーワードを入れる。
2. 利用者は Enter を押すか「検索」ボタンを押す。
3. 画面は、キーワードを名前に含むアイテムを結果表に表示する。

### J2: スロット・ジョブ・iLv119 で絞り込む（→ S2）

1. 利用者はスロットの選択欄でスロットを選ぶ。画面はすぐに検索し直す。
2. 利用者はジョブの選択欄でジョブを選ぶ。画面はすぐに検索し直す。
3. 利用者は「iLv119のみ」のチェックを切り替える。画面はすぐに検索し直す。

### J3: フィルター行で絞り込む（→ S3）

1. 利用者は「+ フィルター追加」を押してフィルター行を足す。
2. 利用者はフィルター行のアイテム項目・演算子を選び、値を入れるか選ぶ。必要なら行を足すか「×」で消す。
3. 利用者は「検索」ボタンを押す。画面はフィルター行を含めた検索条件で検索し直す。

### J4: 並べ替える（→ S4）

1. 利用者はソート基準の選択欄でソート基準を選ぶか、結果表の列見出し「名前」「Lv」「iLv」のどれかを押す。
2. 説明文ステータスソートを選んだときは、利用者はステータス名の欄にステータス名（例: STR、攻）を入れて Enter を押す。
3. 利用者は昇順・降順の選択欄で順序を切り替える。
4. 画面は並べ替えた結果を表示する。説明文ステータスソートのときは、各アイテムの説明列で、並べ替えの値を読んだ箇所を強調する。

### J5: ページを送る（→ S5）

1. 利用者は結果の下の「次へ」を押して次のページを見る。
2. 利用者は「前へ」を押して前のページに戻る。

## 受け入れ基準

### 全体

- **AC1**: URL `#/search` か、その後ろに検索条件を載せた `#/search?...`（AC41）を開くと装備検索画面を表示する。`search.html` を開くと URL が `#/search` に置き換わり、装備検索画面を表示する。
- **AC2**: 装備検索画面を初めて表示したとき、URL に検索条件が無ければ、次の既定の検索条件で検索した 1 ページ目を表示する: キーワードは空、スロットは「全スロット」、ジョブは「All Jobs」、「iLv119のみ」はオン、フィルター行は無し、ソート基準は「名前」、順序は「昇順」。
- **AC3**: 装備検索画面から別の画面へ移って戻ったとき、検索条件の入力欄・結果表・表示中のページは移る前と同じである。ブラウザでアプリを再読み込みしたときは、URL に検索条件があれば AC42 のとおりその検索条件で検索した 1 ページ目を表示し、無ければ AC2 の既定の検索条件に戻る。
- **AC4**: 利用者の操作による検索の実行のきっかけは次の 5 つだけである。(1) スロット・ジョブ・「iLv119のみ」・ソート基準・昇順降順のいずれかの変更、(2) 検索欄またはステータス名の欄での Enter（IME の変換を確定する Enter を除く）、(3) 「検索」ボタン、(4) ステータス名の欄からフォーカスが外れ、かつ欄の値が直前の検索に使った値と異なるとき（フォーカスが外れたきっかけが「次へ」「前へ」の押下でも同じ。そのときの扱いは AC37）、(5) 結果表の列見出し「名前」「Lv」「iLv」の押下。(1)〜(5) の検索は、その時点の検索条件の入力欄（検索欄・フィルター行・ステータス名の欄を含む）の内容をすべて使う。フィルター行の追加・編集・削除だけでは検索しない。ページ送り（AC36）は検索条件を変えずに表示するページだけを変える。
- **AC5**: ページ送り（J5）以外のきっかけで検索したとき、結果は 1 ページ目から表示する。
- **AC6**: 結果表は「名前」「Lv」「iLv」「ジョブ」「スロット」「説明」の 6 列をこの順で持ち、1 行が 1 アイテムである。
- **AC7**: 結果表の各列は次のとおり表示する。
  - 「名前」: アイテムの日本語名。日本語名が空のアイテムは英語名
  - 「Lv」: 数値（すべてのアイテムが Lv を持つ）
  - 「iLv」: 数値。iLv を持たないアイテムは「-」
  - 「ジョブ」: 装備可能ジョブを 1 文字の略記（戦・モ・白・黒・赤・シ・ナ・暗・獣・吟・狩・侍・忍・竜・召・青・コ・か・踊・学・風・剣）にし、この並びの順に区切り文字を挟まずつないだもの。22 ジョブすべてなら「All Jobs」、1 つも無ければ「-」
  - 「スロット」: 装備できるスロットのスロット区分を、用語「スロット区分」の並びの順に半角空白で区切ったもの。同じスロット区分は 1 回だけ出す（例: 左耳と右耳の両方に着けられるアイテムは「耳」）。1 つも無ければ「-」
  - 「説明」: 日本語のアイテム説明文。説明文の中の改行は改行として表示する。日本語のアイテム説明文が無いアイテムは空欄
- **AC8**: 結果の上の件数表示は、アイテムデータの読み込み中は「読み込み中...」、検索後は検索条件に合うアイテムの総数 N を、3 桁ごとに「,」で区切って「N 件」と表示する（例:「12,345 件」）。検索条件に iLv119 絞り込みが含まれ（AC14）、iLv119 絞り込み以外の条件をすべて満たすのに iLv119 絞り込みで除いたアイテムが M 件（M は 1 以上）あるときは、「N 件（iLv119 絞り込みで M 件を除外）」と表示する。M も 3 桁ごとに「,」で区切る。検索条件に合うアイテムが 1 件も無いときは「0 件」（M が 1 以上なら「0 件（iLv119 絞り込みで M 件を除外）」）と表示し、結果表の代わりに「該当する装備がありません」と表示する。
- **AC9**: アイテムデータの読み込みに失敗したとき、結果表の代わりに「データの読み込みに失敗しました: 」に続けて失敗の理由を表示する。
- **AC38**: キーワード・フィルター行の入力欄の値・ステータス名は、前後の空白（全角空白を含む）を除いてから空かどうかを判定し、除いた後の値で検索する。例えば空白だけを入れた検索欄は空のキーワード（AC10）として、空白だけを入れた数値型のフィルター行は値が空の行（AC20）として扱う。
- **AC41**: 検索を実行するたび（AC2 の初回の検索と AC4 のきっかけ）、URL をその検索に使った検索条件のすべて（キーワード・スロット・ジョブ・「iLv119のみ」のオン・オフ・フィルター行・ソート基準・昇順か降順か・ステータス名）を載せた `#/search?...` に置き換える。置き換えはブラウザの履歴に新しい項目を積まず、今の履歴の項目の URL を書き換える。表示中のページの位置は URL に載せず、ページ送り（AC36）では URL を変えない。
- **AC42**: 検索条件を載せた `#/search?...` を開いたとき（再読み込みを含む）、URL の検索条件を入力欄に入れ、その検索条件で検索した 1 ページ目を表示する。URL の中で読めない条件（値がその条件の選択肢に無いもの、または条件の形式に合わないもの）は、その条件だけ AC2 の既定値にし（フィルター行では、その行を足さない）、残りの条件は URL のとおりに使う。読めない条件があったことは利用者に知らせない。

### J1: 名前で探す

- **AC10**（手順 1〜3）: キーワードが空でないとき、結果はアイテムデータの 4 つの名前の欄（`en`・`ja`・`enl`・`jal`）のどれかにキーワードを部分文字列として含むアイテムだけになる。キーワードが空のときは名前で絞らない。
- **AC11**（手順 1〜3）: 名前の一致を判定する前に、キーワードと名前の両方で、カタカナをひらがなに、全角の英字と数字を半角に、英字を小文字に置き換える。例えば「ヒポメネソックス」「ひぽめねそっくす」のどちらのキーワードでも、名前「ヒポメネソックス」を含むアイテムが見つかる。

### J2: スロット・ジョブ・iLv119 で絞り込む

- **AC12**（手順 1）: スロットの選択肢は「全スロット」と、スロット区分 14 個（メイン・サブ・レンジ・矢弾・頭・胴・両手・両脚・両足・首・腰・耳・指・背）の 15 個である。「全スロット」以外を選ぶと、結果はそのスロットに着けられるアイテムだけになる。「耳」は左耳と右耳のどちらか、「指」は左指と右指のどちらかに着けられるアイテムを含む。
- **AC13**（手順 2）: ジョブの選択肢は「All Jobs」と 22 ジョブ（AC7 の略記で表示）の 23 個である。ジョブを選ぶと、結果はそのジョブが装備できるアイテムだけになる。
- **AC14**（手順 3）: 「iLv119のみ」のチェックは、スロットの選択欄（AC12）が「全スロット」・メイン・サブ・レンジ・頭・胴・両手・両脚・両足 のときだけ表示し、それ以外のスロット（矢弾・首・腰・耳・指・背）では表示しない。表示していない間は iLv119 絞り込みを検索条件に含めない。表示に戻ったとき、チェックは隠れる前のオン・オフを保つ。
- **AC15**（手順 3）: 「iLv119のみ」がオンで、スロットが「全スロット」以外のとき、結果は iLv が 119 のアイテムだけになる。
- **AC16**（手順 3）: 「iLv119のみ」がオンで、スロットが「全スロット」のとき、メイン・サブ・レンジ・頭・胴・両手・両脚・両足 の 8 スロットのどれかに着けられるアイテムは iLv が 119 のものだけ残す。8 スロットのどれにも着けられないアイテム（着けられるスロットを持たないアイテムを含む）は iLv に関係なく残す。

### J3: フィルター行で絞り込む

- **AC17**（手順 1）: 「+ フィルター追加」を押すと、フィルター行が 1 行増える。新しい行のアイテム項目は「ID」、演算子は「=」、値は空である。
- **AC18**（手順 2）: アイテム項目の選択肢は次の 12 個で、項目ごとに型が決まっている。
  - 数値: ID・Level・Item Level・Damage・Delay・Skill
  - 文字列: Name (EN)・Name (JA)・Category
  - 配列: Jobs・Slots・Races

  値は、Jobs・Slots・Races・Category・Skill の行では選択欄で選び（選択肢は AC39）、それ以外の行では入力欄に入れる。
- **AC19**（手順 2）: 演算子の選択肢はアイテム項目の型で決まる。数値は「=」「!=」「>=」「<=」「>」「<」、文字列は「contains」「=」「!=」「starts with」「ends with」、配列は「contains」「not contains」である。アイテム項目を変えると、演算子はその型の選択肢の先頭に戻る。
- **AC20**（手順 3）: 値が空のフィルター行（値が選択欄の行では、選択欄が未選択の行）は検索条件に使わない。値が空でないフィルター行が複数あるとき、結果はすべての行を満たすアイテムだけになる。
- **AC21**（手順 3）: 数値型の行は、アイテムの値と入力した値を数として比べる。入力した値（前後の空白を除く）を数として読めない行は、どのアイテムも満たさない。アイテムがその項目の値を持たないとき（防具の Damage・Delay・Skill、iLv を持たないアイテムの Item Level）、そのアイテムは演算子が「!=」の行だけを満たす。
- **AC22**（手順 3）: 文字列型の行は、比べる前に、アイテムの値と入力した値の両方で、カタカナをひらがなに、全角の英字と数字を半角に、英字を小文字に置き換える（AC11 のキーワードと同じ置き換え）。例えば Name (JA) の行「contains」「ひぽめね」は、名前「ヒポメネソックス」のアイテムを満たす。Name (EN) の行はアイテムデータの `en` の欄だけと、Name (JA) の行は `ja` の欄だけと比べる（`enl`・`jal` の欄とは比べない）。Category の行は、選んだ選択肢の文字列（「Weapon」か「Armor」）とアイテムのカテゴリを比べる。
- **AC23**（手順 3）: 配列型の行の「contains」は、選んだ選択肢に当たる要素をアイテムのその項目が持つとき満たす。Slots の「耳」は左耳か右耳、「指」は左指か右指のどちらかを持つとき満たす。例えば「Jobs」「contains」「戦」は戦士が装備できるアイテムを満たす。「not contains」は「contains」を満たさないとき満たす。
- **AC24**（手順 2）: フィルター行の「×」を押すと、その行が消える。
- **AC39**（手順 2）: 値の選択欄の選択肢は、未選択の状態に加えて、アイテム項目ごとに次のとおりである。
  - Jobs: AC7 の 1 文字の略記 22 個（戦〜剣）。選択肢はアイテムデータの「WAR」形式の要素に 1 対 1 で当たる
  - Slots: スロット区分 14 個。「耳」はアイテムデータの左耳と右耳の要素に、「指」は左指と右指の要素に当たり、それ以外は 1 つの要素に当たる
  - Races: 「ヒューム♂」「ヒューム♀」「エルヴァーン♂」「エルヴァーン♀」「タルタル♂」「タルタル♀」「ミスラ」「ガルカ」の 8 個。それぞれアイテムデータの Hum_M・Hum_F・Elv_M・Elv_F・Tar_M・Tar_F・Mit_F・Gal の要素に当たる
  - Category: 「Weapon」「Armor」の 2 個
  - Skill: 武器のスキルの名前 18 個（格闘・短剣・片手剣・両手剣・片手斧・両手斧・両手鎌・両手槍・片手刀・両手刀・片手棍・両手棍・弓術・射撃・投てき・弦楽器・管楽器・風水鈴）。選ぶと、アイテムデータでそのスキルを表す数値を値として AC21 のとおり比べる
- **AC40**（手順 2）: アイテム項目を変えたとき、変える前と変えた後の値がどちらも入力欄なら、値の欄の内容を残す。どちらか一方でも選択欄なら、値は空（選択欄では未選択）に戻る。

### J4: 並べ替える

- **AC25**（手順 1・3）: ソート基準の選択肢は「名前」「Lv」「iLv」「カテゴリ」「説明文ステータス」の 5 個、順序の選択肢は「昇順」「降順」の 2 個である。
- **AC26**（手順 2）: ステータス名の欄は、ソート基準が「説明文ステータス」のときだけ表示する。
- **AC27**（手順 4）: 結果は次の順で並べる。前の規則で順位が付かないときだけ次の規則を使う。
  1. 名前の末尾の「+数字」の数が大きいものを先にする。名前は日本語名を使い、日本語名が空なら英語名を使う。末尾が「+数字」でない名前は 0 とみなす。この規則は昇順・降順とソート基準に関係しない
  2. ソート基準と順序（AC28〜AC30）
  3. 1・2 で順位が付かないアイテムは、アイテムデータの並び順を保つ
- **AC28**（手順 4）: ソート基準「名前」は、日本語名（日本語名が空なら英語名）に AC11 と同じ置き換え（カタカナをひらがなに、全角の英字と数字を半角に、英字を小文字に）をかけたものを、Unicode のコードポイントの順で比べる。例えば昇順では、名前「あ」で始まるアイテムと「ア」で始まるアイテムは、どちらも「い」「イ」で始まるアイテムより前に並ぶ。「カテゴリ」は「Armor」「Weapon」の文字列の順で比べる。
- **AC29**（手順 4）: ソート基準「Lv」「iLv」は数値で比べる。iLv を持たないアイテムは、昇順でも降順でも、iLv を持つアイテムより後ろに並ぶ。
- **AC30**（手順 2・4）: 説明文ステータスソートでは、各アイテムについて次の値で比べる。ステータス名の欄が空のときは、AC27 の 1・3 だけで並べる。
  - 読むテキストは日本語のアイテム説明文だけである。英語のアイテム説明文は読まない（0004-equip-interpretation.md の AC2 と同じ）
  - ステータス名を 0004-equip-interpretation.md のユーザー定義プロパティの名前 X とみなし、0004 の AC18・AC20・AC21 の規則で X の値の表記を探す。条件ラベルとラベルの適用範囲にある表記は読まない（0004 の用語「条件ラベル」、AC5・AC6）。例えばステータス名「攻」で並べると、説明文 `魔攻+5 攻+10` の値は 10 である（`魔攻` の中の「攻」は直前に区切りが無いので一致しない）
  - 値の表記が複数あれば、テキストの中で最初の 1 件の値だけを使う。ユーザー定義プロパティはすべて足す（0004 の AC19）ので、同じアイテムでも説明文ステータスソートの値とユーザー定義プロパティの値は異なることがある。例えばステータス名「命中」で並べると、説明文 `命中+5 命中+3` の値は 5 である
  - 値の表記が 1 つも見つからないアイテム（日本語のアイテム説明文が無いアイテムを含む）は、昇順でも降順でも、値の表記が見つかったアイテムより後ろに並ぶ（AC27 の 2 で比べるとき）。値の表記が見つからないアイテムどうしは AC27 の 3 で並ぶ
- **AC31**（手順 1）: 列見出し「名前」「Lv」「iLv」を押したとき、その列が今のソート基準なら順序を反転して検索し、そうでなければソート基準をその列にし、順序を昇順にして検索する。列見出し「ジョブ」「スロット」「説明」は押しても何も起きない（検索せず、ソート基準も順序も変わらない）。
- **AC32**（手順 4）: 直前の検索のソート基準が「名前」「Lv」「iLv」のとき、その列見出しに昇順なら「▲」、降順なら「▼」を付ける。それ以外のソート基準では、どの列見出しにも印を付けない。
- **AC33**（手順 4）: 直前の検索が説明文ステータスソートでステータス名が空でないとき、説明列は、各アイテムで AC30 の値を読んだ箇所（ステータス名から数字の末尾まで）だけを強調して表示する。値を読んだ箇所が無いアイテムでは何も強調しない。ステータス名が記号（例えば `(`・`*`・`+`）を含んでいても、画面は表示を続け、強調の位置は AC30 で値を読んだ箇所と一致する。

### J5: ページを送る

- **AC34**（手順 1・2）: 1 ページは 50 件である。検索条件に合うアイテムの総数が 50 件以下なら、ページ送りの部品を表示しない。
- **AC35**（手順 1・2）: ページ送りの部品は「前へ」ボタン・「Page X of Y」（X は表示中のページ番号、Y は総ページ数）・「次へ」ボタンからなる。1 ページ目では「前へ」を押せず、最後のページでは「次へ」を押せない。
- **AC36**（手順 1・2）: 「次へ」を押すと次のページを、「前へ」を押すと前のページを、直前の検索の検索条件のまま表示する。直前の検索の後に検索欄・フィルター行・ステータス名の欄を変えていても、ページ送りはその変更を検索条件に使わず、入力欄の内容は変えずに残す。ただし、ステータス名の欄の値が直前の検索に使った値と異なり、欄にフォーカスを置いたまま「次へ」か「前へ」を押したときは、ページ送りをせずに AC37 に従う。
- **AC37**（手順 1・2）: ステータス名の欄の値を直前の検索に使った値から変え、欄にフォーカスを置いたまま「次へ」か「前へ」を押したとき、フォーカスが外れたことによる検索（AC4 の (4)）だけを行い、新しい検索条件の 1 ページ目を表示する。押した「次へ」「前へ」によるページ送りは行わない。欄の値が直前の検索に使った値と同じなら、AC4 の (4) の検索は起きず、AC36 のとおりページを送る。

## 制約

- アイテムデータは Windower/Resources の `items.lua` と `item_descriptions.lua` から CI のビルド時に生成し、リポジトリには置かない。上流の変化は 1 日 1 回の定期実行で取り込む（出典: [ADR 0003](../adr/0003-items-json-generated-in-ci.md)）
- アイテムデータは WASM バイナリに埋め込んで配り、画面はアイテムデータを別のファイルとして取得しない（出典: [ADR 0009](../adr/0009-embed-item-data-in-binary.md)）
- 名前での絞り込み・スロット・ジョブ・iLv119・フィルター行による絞り込み、並べ替え、ページ分けは Rust 側で行い、画面は検索条件を渡して 1 ページ分の結果を受け取る（出典: [ADR 0010](../adr/0010-equipment-interpretation-in-rust.md)）
- ソート基準「名前」は Unicode のコードポイントの順で比べる。移植前の JS 実装（`localeCompare`）の並びとは一致しない（出典: [ADR 0010](../adr/0010-equipment-interpretation-in-rust.md)）
- ソート基準「名前」は、比べる前に名前へ AC11 と同じ置き換えをかける（出典: この grill で決定: 名前で探すとき（AC11）と並べるときで名前の扱いを揃え、ひらがなで始まる名前がすべてカタカナで始まる名前より前に固まらないようにするため。置き換えは名前で探すときの関数をそのまま使えるので WASM は大きくならない / 却下案: 置き換えをかけず、並びの改善は D2 でまとめて決める）
- 優先並び（AC27 の 1）は、ソート基準と順序より先に必ず適用する（出典: この grill で決定: 強化段階が高いもののほうを先に見たり優先的に選んだりするケースが多いため（S6） / 却下案: ソート基準で順位が付かないときの並べ方に下げる）
- スロットを選んだときに iLv が 119 のアイテムを先にする並べ替えは持たない（出典: この grill で決定: 「iLv119のみ」がオンなら結果は最初から iLv 119 だけなので働かず、オフなら iLv 119 以外も同列に見たい利用者の意図に反するため / 却下案: 今のまま優先並びとして残す、ソート基準で順位が付かないときの並べ方に下げる）
- 装備検索画面のルートは `#/search` とする。装備検索画面は初回表示まで生成を遅らせ、生成した後は表示の切り替えだけで状態を保つ。旧 URL の `search.html` は `#/search` へのリダイレクトとして残す（出典: [ADR 0013](../adr/0013-sidebar-spa-mantine.md)）
- 説明文ステータスソートは、値の表記・条件ラベル・ラベルの適用範囲を、ユーザー定義プロパティの値を拾う規則と同じ実装で探す（出典: [ADR 0018](../adr/0018-equip-module-owns-interpretation.md)）
- 説明文ステータスソートは 1 つのテキストで最初の 1 件の値だけを使い、ユーザー定義プロパティ（すべて足す）とは値が異なりうる（出典: この grill で決定: ユーザー定義プロパティはステータスの計算で組み込みプロパティと同じく足し合わせて表示するのですべて足すことにした（0004 の制約）が、説明文ステータスソートの読み方は今のまま変えないと決めた / 却下案: 説明文ステータスソートとユーザー定義プロパティを同一の挙動にする（ADR 0015 を改訂する））
- 説明列の強調表示の位置は、説明文ステータスソートが値を読む実装から求め、画面側で別の規則を持たない（出典: この grill で決定: 規則を 1 箇所にし、記号を含むステータス名とラベルの適用範囲で、並べ替えの値と強調の位置が食い違わないようにするため / 却下案: 画面側でステータス名をエスケープするだけにする、強調表示をやめる）
- 説明文ステータスソートは英語のアイテム説明文を読まない。日本語のアイテム説明文が無いアイテムは、値の表記が見つからないアイテムと同じに扱う（出典: この grill で決定: 装備セットのステータスは英語の説明文を読まない（0004 の AC2）ので、英語の説明文で代わりに読むと検索の順位と装備したときの値が食い違い、英語では `Pet:` などが条件ラベルにならず日本語のステータス名も一致しないため / 却下案: 日本語のアイテム説明文が無いときの代わりとして英語のアイテム説明文を読む（ADR 0019 を改訂する））
- フィルター行の Jobs・Slots・Races・Category・Skill の値は、アイテムデータの内部の表記を利用者に入れさせず、選択欄で選ばせる（出典: この grill で決定: 結果表は「戦」「胴」と表示するのに値は「WAR」「body」と入れる必要があり、表示どおりに入れるとどれにも一致しない。Skill は武器スキルの数値で利用者には意味が分からない / 却下案: 今のまま入力欄にし、要素名の一覧を AC に書く。アイテム項目名と演算子も日本語にする）

## 設計上の論点

- **D1**: 検索の応答性をどう測り、どの値を超えたら検索用インデックスを別に配る案（ADR 0010 の選択肢 2）へ移るか。ADR 0010 は応答性を実測しておらず、移る基準の数値も無い。また ADR 0010 は検索がキーストロークごとに走る前提で応答性を見込んでいるが、この仕様書では検索は AC4 のきっかけごとにだけ走る。測り方と基準を決めたら、その基準を受け入れ基準にする。
- **D2**: ソート基準「名前」の並びを、AC28 の置き換えの後に残る差（漢字の読みの順など）について五十音順に近づけるか。近づけるなら、照合ライブラリを入れる方法（WASM が大きくなる）を採るか（`docs/internal/tech-debt/equip-stats-js-quirks.md` の 5 節）。
- **D3**: 強調表示の位置（AC33）を、Rust 側から画面へどの形で返すか（検索結果の各アイテムに、値を読んだ箇所の文字の範囲を添えるか、強調済みのテキストを返すか）。範囲で返すなら、Rust 側が全角英数を半角に寄せた後のテキストで数えた位置と、画面に表示する説明文の位置の対応も決める。Rust 側で元の説明文の位置に戻してから返す案も候補にする。
- **D4**: アイテムデータの `enl`・`jal` の欄が何の名前か（キーワードの照合 AC10 に使っている）を、生成したアイテムデータで確かめて用語節に定義する。
- **D5**: Skill・Category の行で、値を選択欄で選ぶようにした後も型ごとの演算子（Skill の「>=」「<」など、Category の「contains」「starts with」など）を残すか。Skill の数値の大小はスキルの順序として意味を持たない。
- **D6**: 検索条件を URL に載せる実装（AC41・AC42）。ハッシュで画面を判定する処理（`web/src/routing.ts` の `parseHash`）が `?` 以降を無視して `#/search?...` を装備検索画面と判定するように直すこと、検索条件（フィルター行を含む）を URL の文字列にする形式、履歴を積まない置き換えの方法、装備検索画面を生成した後に検索条件の違う `#/search?...` へハッシュが変わったとき（リンクを開き直したときなど）とサイドバーから検索条件の無い `#/search` へ戻ったときの扱いを決める。
