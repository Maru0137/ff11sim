# 0014. 装備スロットを表示専用 4x4 グリッドにし、編集を Mantine Modal に集約する

## Context and Problem Statement

装備セットビューは、ステータスパネルの下に 16 スロットの行 (検索入力・説明・
オーグメント・カスタム説明が横並び) を縦に積む 1 カラム構成で、装備表示だけで
縦 800px 超を占めていた。装備を選ぶ操作とステータスを確認する操作が画面の
上下に分かれ、往復のたびにスクロールが必要になる。表示を FF11 の装備画面と
同じ 4x4 グリッドへコンパクト化するにあたり、(a) 行に横並びしていた編集 UI
(検索・オーグメント・カスタム説明) をどこへ移すか、(b) その編集 UI を何で
実装するかを決める必要がある。

## Decision Drivers

* **スクロールの解消** — 装備を変えながらステータスを同一画面で確認できること
* **表示のコンパクト化** — FF11 準拠の 4x4 グリッド (ユーザーレビュー済みの
  モックに準拠)
* **既存の状態管理を変えないこと** — equipState (可変オブジェクト +
  バージョン購読) と保存データ形式は無改修で済ませる
* **既存実装の再利用** — 検索 UI は装備検索ビュー (ResultsTable) が既にある
* **共有閲覧モード** (?share=) で編集 UI が露出しないこと
  ([ADR 0013](0013-sidebar-spa-mantine.md) の「構造的排除」方針)
* Mantine 段階導入 (ADR 0013) との整合 — コンポーネント移行の既定路線に
  乗るか、手書きモーダル CSS を増やすか

## Considered Options

1. インライン 16 行リストを維持し、配置調整のみで対応する
2. 表示専用 4x4 グリッドにし、編集をセルクリックで開く UI に集約する
    - 2.1. 選択 UI: セル内のインクリメンタル検索ドロップダウン (現行踏襲)
    - 2.2. 選択 UI: 検索モーダル (ResultsTable 流用)
    - 2.3. 選択 UI: グリッド脇の固定詳細パネル
3. モーダルの実装: 既存 modal-store + 手書き CSS パターン
4. モーダルの実装: Mantine Modal

1〜2 はスロット表示と編集 UI の配置の軸、3〜4 は (2.2 を採る場合の) モーダル
実装手段の軸で直交する。

## Decision Outcome

選択: **2 + 2.2 + 4. 表示専用グリッド + 検索モーダル (Mantine Modal)**。

表示と編集を分離しない限り 16 行の縦積みは崩せず、配置調整 (案 1) では
スクロール問題が残る。セルは表示専用 (装備名 + 説明要約 1 行 + Aug/メモ
バッジ) に絞り、検索・オーグメント・カスタム説明の編集はモーダルへ集約した。
選択 UI は、絞り込み表示 (Lv/iLv/ジョブ/説明) が既に揃っている ResultsTable
を流用できるモーダルとし、モーダル実装は ADR 0013 が既定路線とした Mantine
コンポーネント移行の最初の適用として Mantine Modal を採った。

- グリッド順は FF11 の装備画面準拠 (`EquipGrid.tsx` の `GRID_ORDER`)。
  データ定義順 (`data/equipment_slots.json`) とは独立
- グリッドとステータスパネルは左右 2 カラム (`.equipset-columns`、1100px 以下
  で縦積み)。グリッドは sticky にしてスクロール中も視界に残す
- 行クリックで装備を選択してもモーダルは閉じない (続けてオーグメント・
  カスタム説明を設定するため)
- ResultsTable の流用は `.search-page` ラッパで search.css のスコープに乗せる
  (ADR 0013 で確立したスコープ化の応用)。DOM id は流用しない
  (検索ビューと同時マウントされるため。Pagination の id はオプション化)
- Mantine の利用はモーダル枠 (Modal) のみ。内部の入力は index.css の既存
  手書きパターン (素の input/select) に乗せ、裸の select/input グローバル
  ルールと Mantine input 系の干渉 (ADR 0013 の既知の残課題) を持ち込まない
- zIndex は 900 を明示する。AppShell (200) より上、レガシーモーダル
  (`.modal-backdrop`, 1000) より下に置き、モーダル内から開くカスタム Aug
  ヘルプが正しく重なるようにする
- 既存 3 モーダル (modal-store + 手書き CSS) は温存する。新規モーダルから
  Mantine を使う
- 共有閲覧モードはモーダルを読み取り専用の分岐でレンダリングする (旧実装の
  「CSS で入力を無効化」は廃止し、編集 UI を構造的に出さない)
- 状態管理は無改修。書き込みは従来どおり `getSlots()[key]` の mutate →
  `updateEquipEditStatus()` の 1 経路

### Consequences

* Good: 装備変更とステータス確認が同一画面に収まり、往復スクロールが不要に
  なった (装備表示は約 800px → 4 行分に圧縮)
* Good: モーダルの検索は装備検索ビューと同じ表形式 (Lv/iLv/ジョブ/説明) に
  なり、旧ドロップダウン (装備名のみ表示) より選択時の情報量が増えた
* Good: focus trap・ESC・スクロールロックを自作せず Mantine に委譲できた
* Bad: 装備の説明全文がグリッド上で読めなくなった (セルは 1 行要約 + title
  属性。全文はモーダルを開いて確認する)
* Bad: 装備 1 つの変更に「セルクリック → 選択 → 閉じる」の操作が増えた
  (旧 UI は行内で完結)
* Bad: Mantine コンポーネントと手書き CSS の混在が (ADR 0013 のレイアウト
  限定から) モーダルにも広がり、裸の h2 ルール打ち消しのような調整が必要
  だった (`equip-grid.css`)
* Neutral: モーダル実装が 2 系統 (modal-store + Mantine) 併存する。既存 3
  モーダルの移行は必要になるまで行わない

### Confirmation

* Playwright スモークテスト (`tests/smoke.spec.js`) が検証する:
  - 「スロット検索で装備を選び、装備セットを保存できる」— セルクリック →
    モーダルの結果テーブル行クリック → 閉じてセルに装備名表示 → 保存 →
    再読込後の残存
  - 「オーグメント選択でテキストとステータスが更新される」— モーダル内の
    Aug パス選択・カスタム説明入力がステータス集計へ反映され、閉じた後の
    セルに Aug/メモ バッジが出ること
  - 「検索結果のページネーションで次のページへ進める」— 検索ビュー側の
    `#pagination` 等の id が (モーダルの id オプション化後も) 機能すること
* セル要約の純関数は `web/src/equip/equip-summary.test.ts` (Vitest) が検証する
* 共有閲覧モードのスモークテストは編集 UI の非表示のうちナビ非表示のみを
  機械検証しており、モーダルの読み取り専用分岐を検証するテストはない。
  レビューと目視で確認する

## Pros and Cons of the Options

### 1. インライン 16 行リストを維持し、配置調整のみで対応する

* Good: 実装コスト最小。既存の操作感 (行内で編集が完結) を維持できる
* Bad: 1 行に検索・説明・Aug・カスタムを横並びさせる限り行高を圧縮できず、
  16 行の縦積み (800px 超) が残る。2 カラム化してもステータスと並ばない
* Bad: モバイルの縦積みカード (行毎 5 段) も維持することになる

### 2. 表示専用 4x4 グリッド + 編集の集約 (採用)

* Good: 装備表示が 4 行に収まり、ステータスとの 2 カラム配置が成立する
* Good: セルが「何を装備しているか」の一覧性に専念でき、FF11 の装備画面と
  同じメンタルモデルになる
* Bad: 編集に 1 クリック (セルを開く操作) が挟まる

#### 2.1. セル内のインクリメンタル検索ドロップダウン (現行踏襲)

* Good: 実装の移植が最小で、行内編集の操作感を残せる
* Bad: セル幅 (約 130px) では入力・候補表示が窮屈で、オーグメント・
  カスタム説明を置く場所が結局セル外に必要になる
* Bad: 候補が装備名のみの表示に留まり、選択時の情報量が乏しい (旧 UI の
  既知の弱点をそのまま持ち越す)

#### 2.2. 検索モーダル (ResultsTable 流用) (採用)

* Good: 装備検索ビューと同じ表形式・絞り込み (IL119) が使え、選択・Aug・
  カスタム説明を 1 箇所に集約できる
* Good: `.search-page` スコープ化 (ADR 0013) のおかげで CSS 無改造で流用
  できた
* Bad: モーダルという新しいレイヤが増え、z-index・フォーカス管理の考慮が
  必要 (Mantine に委譲して緩和)

#### 2.3. グリッド脇の固定詳細パネル

* Good: モーダルを開かずに編集でき、選択スロットの切替も速い
* Bad: 2 カラム (グリッド + ステータス) に加えて第 3 の領域が必要になり、
  スクロール解消のための横幅が足りなくなる
* Bad: 「選択中スロット」という新しい UI 状態を常時管理することになる

### 3. モーダルの実装: 既存 modal-store + 手書き CSS パターン

* Good: 既存 3 モーダルと実装が揃い、CSS パターンも実績がある
* Bad: modal-store はレガシー JS からも開くための大域ストアで、React 内
  (セルクリック) からしか開かないモーダルには過剰。ローカル state で足りる
* Bad: focus trap・ESC・スクロールロックが無く、自作すると保守が増える

### 4. モーダルの実装: Mantine Modal (採用)

* Good: focus trap・ESC・overlay・モバイル fullScreen が宣言的に手に入る
* Good: ADR 0013 の「Mantine コンポーネントへの段階移行」の既定路線に乗る
  最初の実例になる
* Bad: 手書き CSS との混在範囲が広がる (裸の h2 ルールの打ち消し等、
  カスケードの調整が必要だった)
* Bad: zIndex 既定値 (200) が AppShell と同値のため、明示指定 (900) を
  忘れると重なり事故が起きる
