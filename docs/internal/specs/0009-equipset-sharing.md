# 装備セットの共有

この仕様書の用語は [用語集](../../../CONTEXT.md) と、依存する仕様書（[0002 キャラクターの管理](0002-character-management.md)、[0006 装備セットの編集](0006-equipset-editing.md)、[0008 ステータスの表示](0008-status-display.md)、[0003 ステータスビューの管理](0003-status-view-management.md)、[0001 保存と同期](0001-saving-and-sync.md)、[0007 ステータスの計算](0007-status-calculation.md)）の用語節に従う。この仕様書で定義する語は「用語」節に書く。

## 用語

**共有**:
装備セットを、そのステータスを再現するのに要る情報（キャラクタースナップショットとサポートジョブ（→ 0006））と一緒に変更できない記録として公開し、共有 URL を知る人なら誰でも見られるようにすること。共有した後に元の装備セットを編集しても、共有した内容は変わらない。
「1 つの共有」と数えるときは、1 回の発行で作られた記録 1 件を指す。1 つの共有が持つ内容は AC2 に、何を含めるかの基準は「制約」の 1 行目にある。

**キャラクタースナップショット**:
共有を発行した時点で保存されているキャラクター（→ 0002）の複製。閲覧する人が、共有した人と同じステータスを再現するために使う。
キャラクターの編集フォームにある未保存の変更（→ 0001）と、キャラクターの ID（→ 0002）は含まない。閲覧者自身のキャラクターを上書きせず、インポートでも取り込まない。

**共有 URL**:
1 つの共有を指す URL。サイトの origin とパスに `?share=<共有 ID>` を付けた形で、共有 ID は共有を作ったときに発行される UUID。

**共有閲覧モード**:
共有 URL で開いたときの画面の状態。共有された装備セットを、キャラクタースナップショットから求めたステータスと一緒に読み取り専用で表示する。
URL に `share` クエリパラメータがあるかどうかだけで決まり、ハッシュ（`#/...`）は見ない。
共有閲覧モードでの装備セット画面（→ 0006）・ステータス欄と内訳モーダル（→ 0008）・ステータスビュー（→ 0003）の振る舞いは、すべてこの仕様書の J2 に書く。

**共有ヘッダ**:
共有閲覧モードで装備セット画面の上部に出る領域。「共有された装備セット」のバッジは共有ヘッダの一部である。
共有を読み込めたときは、バッジと、共有された装備セットの名前・共有元・キャラクタースナップショットの要約・「このツールを使う」を並べる（AC15・AC16・AC41）。読み込みが終わるまではバッジと「読み込み中…」を（AC42）、読み込めなかったときはバッジと失敗の表示を出す（AC24）。

**共有元**:
共有を作った人の、装備セットが属していたキャラクター。画面上はキャラクター名と、キャラクタースナップショットから組み立てた種族・ジョブ・レベルで示す。

**インポート**:
共有閲覧モードで、共有された装備セットのスロットの装備を、閲覧者自身のキャラクターとジョブに属する新しい装備セットとして保存すること。ログインしていなくても行える。
キャラクタースナップショットは取り込まない。
_使わない_: 取り込み、コピー

## 課題

- **P1**: 装備セットを作った人が、それを他人に見せたい。しかし装備セットだけを渡しても、受け取った側では同じステータスが出ない。ステータスは種族・ジョブレベル・マスターレベル・スキル・メリットポイント・ジョブポイントに依存するため。
- **P2**: 見せられる側は、ログインやキャラクターの登録をしないまま内容を見たい。
- **P3**: 見せられた装備セットを自分のキャラクターで使いたい人が、装備を 1 つずつ選び直す手間をかけたくない。

## ユーザーストーリー

- **S1**: 装備セットを作った利用者として、その装備セットを指す URL を発行して他人に渡したい（→ P1）
- **S2**: 共有 URL を受け取った利用者として、ログインせずに、共有した人と同じステータスで装備セットを見たい（→ P1, P2）
- **S3**: 共有 URL を受け取った利用者として、各装備のアイテム説明文・オーグメント文・カスタム説明と、ステータスの内訳まで確かめたい（→ P1）
- **S4**: 共有 URL を受け取った利用者として、共有された装備セットを自分のキャラクターとジョブの装備セットとして保存したい（→ P3）

## ユーザージャーニー

### 全体の流れ

共有する人は J1 で共有 URL を発行し、SNS やチャットなどで渡す。受け取った人は J2 で閲覧し、必要なら J2 の画面から J3 のインポートに進む。共有閲覧モードから通常の画面に出るときは、共有ヘッダの「このツールを使う」を押す（AC41）。

### J1: 共有 URL を発行する（→ S1）

1. 装備セット画面で、保存済みの装備セットを開く
2. 装備セットの編集フォームの「共有」を押す
3. 開いたモーダルで、共有の内容が URL を知る全員に公開されることを読み、「発行する」を押す
4. 表示された共有 URL を「URL をコピー」でコピーする
5. 「閉じる」でモーダルを閉じる

### J2: 共有された装備セットを閲覧する（→ S2, S3）

1. 共有 URL を開く
2. 共有ヘッダで、装備セットの名前と共有元を確かめる
3. 装備グリッドとステータスを見る
4. スロットを開いて、その装備のアイテム説明文・オーグメント文・カスタム説明を見る
5. ステータスビューを切り替え、内訳を開く

### J3: 共有された装備セットをインポートする（→ S4）

1. 共有閲覧モードで「インポート」を押す
2. インポート先のキャラクター・ジョブを選び、装備セットの名前を入力する
3. モーダルの「インポート」を押す
4. インポートに成功すると、完了の通知が出て、共有閲覧モードではない装備セット画面に移り、インポートした装備セットが開く

## 受け入れ基準

### 全体

- **AC1**: 共有の内容は発行した時点のものに固定される。発行した後に元の装備セットを編集・名前変更・削除しても、元のキャラクターを編集・削除しても、同じ共有 URL で見える内容は変わらない。
- **AC2**: 1 つの共有が持つ内容は次の 7 つである: 装備セットの名前、キャラクター名、ジョブ、発行したときに選んでいたサポートジョブ（→ 0006）、全スロットの装備（アイテム・選んだオーグメント・カスタム説明）、キャラクタースナップショット、テンプレートの選択。テンプレートの選択は、装備セットに保存されたステータスビューの選択（→ 0006）がテンプレート（→ 0003）を指すときだけ持ち、そのテンプレートを指す。キャラクターの ID（→ 0002）、カスタムステータスビュー（→ 0003）を指すステータスビューの選択、ユーザー定義プロパティ（→ 0003）は含まない。
- **AC3**: 共有 URL を知っていれば、ログインしていない人でも閲覧できる。
- **AC38**: 共有の内容を読めるのは、共有 ID を指定して 1 件を読むときだけである。共有 ID を指定せずに共有の記録を一覧で取得することは、ログインしていない人にも、ログインしている人にもできない。ただし、ログインしている人は自分が作った共有の記録だけを取得できる。共有 URL で読んだ内容には、共有を作った人のアカウントの識別子は含まれない。

### J1: 共有 URL を発行する

- **AC4**（手順 1・2）: 「共有」ボタンは、装備セットの編集フォーム（→ 0006）に「保存」「複製」「削除」のボタンと並べて表示される。保存済みの装備セットを開いていて未保存の変更が無いときに押せる。押せない条件のうち未保存の変更があるとき・新規フォームのときと、そのときボタンに添える文言は 0006 の AC55 が、ログインしていないときは AC5 が定める。
- **AC5**（手順 2）: ログインしていない間は「共有」を押せず、ポインタを重ねると「共有するにはログインが必要です」と出る。0006 の AC55 の押せない条件にも当たるときは、0006 の AC55 の文言を出す。
- **AC6**（手順 2）: ログインしている状態で「共有」を押すと、AC8 の場合を除き、「装備セットを共有」という題のモーダルを開き、次の文言と「発行する」「キャンセル」のボタンを表示する。この時点では共有を作らない。文言: 「共有 URL を知っている人は誰でも、ログインせずに、この装備セット（各装備のカスタム説明を含む）と、キャラクター「<キャラクター名>」の内容（種族・各ジョブのレベル・マスターレベル・スキル・メリットポイント・ジョブポイント）を見られます。発行した共有は取り消せません。」
- **AC7**（手順 3）: 「キャンセル」を押すと、共有を作らずにモーダルを閉じる。
- **AC8**（手順 2・3）: キャラクタースナップショットは、「発行する」を押した時点で保存されているキャラクターのうち、装備セットが指すキャラクター（キャラクターの ID で指す → 0006）の、保存されている内容全体からキャラクターの ID を除いた複製である。キャラクターの編集フォームで保存していない変更は含まない。そのキャラクターが保存されていないときは、共有を作らず「装備セットのキャラクターが見つからないため共有できません。」と通知する。「共有」を押した時点（手順 2）で保存されていなければ、モーダルを開かない。「発行する」を押した時点（手順 3）で保存されていなければ、モーダルは AC6 の表示（文言と「発行する」「キャンセル」）のまま残す（AC10 と同じ）。
- **AC9**（手順 3）: 同じ装備セットで共有を発行するたびに新しい共有が作られ、そのたびに異なる共有 URL が発行される。
- **AC10**（手順 3）: 共有の作成に失敗すると「共有 URL の発行に失敗しました: <失敗の理由>」と通知し、モーダルは AC6 の表示（文言と「発行する」「キャンセル」）のまま残す。
- **AC11**（手順 4）: 共有の作成に成功すると、モーダルの「発行する」「キャンセル」を「URL をコピー」「閉じる」に置き換え、共有 URL を読み取り専用の入力欄に表示する。AC6 の文言は表示したまま残す。共有 URL はハッシュ（`#/...`）を含まない。
- **AC12**（手順 4）: 「URL をコピー」を押すと共有 URL をクリップボードに書き込み、ボタンの表示を「コピーしました!」に変え、時間をおいて「URL をコピー」に戻す（戻るまでの時間はこの基準では定めない）。クリップボードへの書き込みに失敗したときは、URL の入力欄の文字列を選択状態にする。
- **AC13**（手順 5）: 「閉じる」を押すとモーダルを閉じる。

### J2: 共有された装備セットを閲覧する

- **AC14**（手順 1）: 共有 URL を開くと、サイドバーを表示せず、見出し「FF11 ステータスシミュレータ」・ログインの操作・装備セット画面だけを表示する。ログインの操作は、ログインしていなければヘッダの「Google でログイン」ボタン、ログインしていればアカウントの表示名と「ログアウト」ボタンである（ボタンの振る舞いは → 0001）。URL にハッシュが付いていても装備セット画面を表示する。
- **AC15**（手順 2）: 共有の読み込みに成功すると、装備セット画面の上部に共有ヘッダを表示する。共有ヘッダは「共有された装備セット」のバッジと、次の 3 つを並べる: 装備セットの名前（空なら「(無名)」）、「共有元: <キャラクター名>」（キャラクター名が空なら「共有元: (未設定)」）、キャラクタースナップショットの要約。
- **AC16**（手順 2）: キャラクタースナップショットの要約は「<種族の略号> <メインジョブの略号><レベル>/<サポートジョブの略号><レベル> ML<マスターレベル>」の形（例: `Hum WAR99/SAM59 ML50`。キャラクタースナップショットに記録された侍のレベルは 99 で、サポートジョブの有効レベルが 59）である。メインジョブは共有のジョブ、サポートジョブは共有のサポートジョブである。メインジョブのレベルはキャラクタースナップショットに記録されたそのジョブのレベル、サポートジョブのレベルはサポートジョブの有効レベル（→ 0007）、マスターレベルはキャラクタースナップショットに記録されたメインジョブのマスターレベルである。メインジョブ・サポートジョブのレベルは 0 でも数字をそのまま出す。種族の略号は `data/races.json` の `key`、ジョブの略号は `data/jobs.json` の `key` を大文字にしたもので、22 ジョブのどれでもないジョブは記録された値をそのまま出す。サポートジョブが無ければ「/」以降のサポートジョブの部分を、マスターレベルが 0 なら「 ML<マスターレベル>」を省く。キャラクタースナップショットを持たない共有（共有の JSON に `character` が無いもの）では、要約を表示しない。
- **AC17**（手順 3）: 共有閲覧モードでは、キャラクター・ジョブ・サポートジョブの選択欄、装備セットのタブ（→ 0006）、名前の入力欄、「保存」「複製」「削除」「共有」の各ボタンを表示しない。「インポート」ボタンを表示する。共有された装備セットの装備・名前を変える操作と、装備セットを保存・複製・削除・並び替えする操作は、画面のどこからも行えない。
- **AC18**（手順 3）: 装備グリッドは、共有された全スロットの装備を表示する。
- **AC19**（手順 3）: ステータス欄（→ 0008）と内訳モーダル（→ 0008）の値は、計算の入力（→ 0007）のうちキャラクターにキャラクタースナップショットを、ジョブ・サポートジョブ・装備に共有された値を、ユーザー定義プロパティ（→ 0003）に閲覧者自身の登録済みのもの（保存先（→ 0001）にあるもの）を使って求める。閲覧者自身のキャラクターは使わない。閲覧者がログインしていなくても、キャラクターを 1 人も登録していなくても、ステータスを表示する。ただし、ステータスが求まらないとき（→ 0007）と、キャラクタースナップショットを持たない共有（共有の JSON に `character` が無いもの）では、ステータスが求まらないときの表示（→ 0008。値のセルはすべて「-」で、2 つの「内訳」ボタンは表示しない）にする。
- **AC20**（手順 4）: 装備グリッドのスロットを押すと装備選択モーダル（→ 0006）を開き、選ばれたアイテムの名前・アイテム説明文と、オーグメント文（選ばれていれば）・カスタム説明（書かれていれば「カスタム: <カスタム説明>」の形）を表示する。装備の検索、オーグメントの選択、カスタム説明の入力、「装備を外す」は表示しない。装備の無いスロットを押したときも装備選択モーダルを開き、「装備が選択されていません。」だけを表示する。
- **AC39**（手順 3）: 共有閲覧モードのステータスの値は、閲覧した時点の計算（→ 0007）とアイテムデータで求める。発行した時点のステータスの値は共有に含めず、発行した時点と値が違いうることは画面に表示しない。
- **AC40**（手順 3）: キャラクタースナップショットに、0002 の AC23 の項目（ジョブレベル・マスターレベル・メリットポイント・ジョブポイント・スキル値）の記録が欠けているときは、記録の補完（→ 0002）と同じ規則（0002 の AC31）で埋めた値を AC19 の計算に使う。共有の記録は書き換えず、埋めた値はどこにも保存しない。
- **AC21**（手順 5）: 共有がテンプレートの選択（AC2）を持つときは、ステータスビューの選択はそのテンプレートで始まる。共有がテンプレートの選択を持たないとき（共有した人がカスタムステータスビューを選んでいたときを含む）と、テンプレートの選択が指すテンプレートが閲覧した時点のテンプレート（→ 0003）に無いときは、テンプレート「待機/防御/回避」で始まる。
- **AC22**（手順 5）: ステータス欄は、共有閲覧モードでないときの装備セット画面と同じく常時表示ビューと選んだステータスビュー 1 つを表示し、ステータスビューの選択欄で選び替えられる。選べるステータスビューは、全テンプレートと、閲覧者自身のカスタムステータスビュー（保存先（→ 0001）にあるもの）である。選び直した結果はどこにも保存されず、再読み込みすると AC21 で始まるステータスビューに戻る。
- **AC23**（手順 5）: ステータス欄の 2 つの「内訳」ボタンを表示し、押すと内訳モーダルを開く（AC19 でステータスが求まらないときの表示にする場合を除く）。ステータスビューの管理画面とカスタムステータスビューの編集画面（→ 0003）に進むボタン（UI 上の表示は「プロパティセット管理」と「このセットを編集」）は表示しない。
- **AC42**（手順 1）: 共有の読み込みが終わるまでは、共有ヘッダに「共有された装備セット」のバッジと「読み込み中…」を表示する。
- **AC24**（手順 1）: 共有の読み込みに失敗したときは、共有ヘッダに「共有された装備セット」のバッジと次の固定の文言だけを表示し、装備グリッド・ステータス欄・「インポート」ボタンは表示しない。共有 ID に対応する共有が無いとき（共有 ID が UUID の形でないときを含む）は「読み込みに失敗しました / 共有された装備セットが見つかりません。」、それ以外の理由で失敗したときは「読み込みに失敗しました / 共有された装備セットを読み込めませんでした。ページを再読み込みしてください。」である。どちらのときも、サーバーやブラウザが返す失敗の理由の文字列は表示しない。
- **AC25**（全手順）: 共有閲覧モードでは、未保存の確認ダイアログも、ページを離れるときの確認（→ 0001）も出さない。
- **AC26**（全手順）: 共有閲覧モードで「Google でログイン」を押してログインしたときの戻り先は、0001 の AC49 に従い、ボタンを押したときの URL（クエリとハッシュを含む）に戻る。共有閲覧モードではその URL が `?share=<共有 ID>` を含むので、ログインした状態で同じ共有の共有閲覧モードに戻る。
- **AC41**（全手順）: 共有の読み込みに成功したときは、共有ヘッダに「このツールを使う」を表示する。押すと、`?share=` を外してハッシュを `#/characters` にした URL に移り、共有閲覧モードではないキャラクター画面（→ 0002）を表示する。

### J3: 共有された装備セットをインポートする

- **AC27**（手順 1）: 「インポート」を押すと、AC28 の場合を除き、ログインしているかどうかにかかわらず、インポートのモーダルを開く。ログインを求めない。
- **AC28**（手順 1）: 閲覧者のキャラクター（ログインしていればアカウントデータの、していなければ端末内データのキャラクター（→ 0001））が 1 人もいないときは、「インポート先のキャラクターがありません。先に「このツールを使う」からキャラクターを作成してください。」と通知し、インポートのモーダルを開かない。
- **AC29**（手順 2）: インポートのモーダルは「共有元: <キャラクター名> / <ジョブの略号> / <装備セットの名前>」を表示する。ジョブの略号は AC16 と同じく `data/jobs.json` の `key` を大文字にしたもので、22 ジョブのどれでもないジョブは記録された値をそのまま出す。キャラクター名・ジョブが空のときはそれぞれ「(未設定)」、装備セットの名前が空のときは「(無名)」と表示する。
- **AC30**（手順 2）: インポート先のキャラクター（UI 上の表示は「対象キャラクター」）は AC28 の閲覧者の全キャラクターから選び、初期値はキャラクター一覧（→ 0002）の並び順の先頭である。インポート先のジョブ（UI 上の表示は「対象ジョブ」。0002 の用語の対象ジョブとは別のもの）の選択肢は、選んでいるインポート先のキャラクターでレベルが 1 以上のジョブ（0006 の AC8 のジョブの選択肢と同じ条件）である。インポート先のジョブの初期値は共有のジョブで、共有のジョブが選択肢に無ければ選択肢の先頭である。インポート先のキャラクターを選び直すと、ジョブの選択肢はそのキャラクターに合わせて変わり、選んでいたジョブが新しい選択肢に無ければ、インポート先のジョブは初期値と同じ規則で選び直される。選択肢が 1 つも無いときは、インポート先のジョブは空である。装備セットの名前（UI 上の表示は「装備セット名」）の初期値は共有の名前（空なら「共有装備セット」）である。
- **AC31**（手順 3）: インポート先のキャラクター・インポート先のジョブ・前後の空白を除いた装備セットの名前のどれかが空なら、「キャラクター・ジョブ・名前を全て指定してください。」と通知し、保存しない。
- **AC32**（手順 3）: 装備セットは、ログインしていればアカウントデータに、ログインしていなければ端末内データに保存する（→ 0001）。アカウントデータの読み込みに失敗している間に保存を止めることも 0001 の規則に従う。
- **AC33**（手順 3）: 保存する名前は、入力した装備セットの名前から前後の空白を除いたものである。保存の直前に保存先から読み直した、選んだキャラクターとジョブの装備セットの一覧に同じ名前の装備セットがあるときは、名前の後ろに「 (2)」「 (3)」… と付けた名前のうち、その一覧でまだ使われていない最初のもので保存する。名前が同じかどうかは、0006 の AC18 と同じく、前後の空白を除いた後の完全一致で決める。既存の装備セットは変更しない。インポートした装備セットは、選んだキャラクターとジョブの装備セットの並び順の末尾に置かれる。
- **AC34**（手順 3）: 保存される装備セットは、新しい装備セットの ID（→ 0006 の AC75）と、選んだキャラクター（キャラクターの ID で指す → 0006）・ジョブ・名前と、共有された全スロットの装備からなる。共有のサポートジョブとキャラクタースナップショットは保存せず、閲覧者のキャラクターも変更しない。ステータスビューの選択（→ 0006）は保存しない。
- **AC35**（手順 4）: 保存に成功すると、インポートのモーダルを閉じ、「「<保存した名前>」としてインポートしました。」と通知し、`?share=` を外してハッシュを `#/equipsets` にした URL に移る。移った先の装備セット画面は、0006 の AC15 のとおり、選んだキャラクターとジョブを選択し、インポートした装備セットを装備セットの編集フォーム（→ 0006）に読み込んだ状態で表示する。画面が移る契機は保存の成功であり、通知の閉じ方（利用者が閉じる・自動で消える）に依らない。
- **AC36**（手順 3）: 保存に失敗すると「インポートに失敗しました: <失敗の理由>」と通知し、モーダルを開いたまま、選んだキャラクター・ジョブ・名前を残す。
- **AC37**（手順 2）: モーダルの「キャンセル」を押すと、何も保存せずにモーダルを閉じる。

## 制約

- 共有には、閲覧する人が共有した人と同じステータスを求めるのに要る情報をすべて含める（サポートジョブはその 1 つ）。ただしユーザー定義プロパティは含めず、閲覧者自身のものを計算に使う（AC19）。機能が増えてステータスの計算に使う情報が増えたときは、この基準で共有に含めるかを決める（出典: この grill で決定: 共有の目的は装備セットの結果のステータスまで見せること。ユーザー定義プロパティを除くのは、共有閲覧モードで選べるカスタムステータスビューは閲覧者自身のもので、その列は閲覧者のユーザー定義プロパティを指すため。組み込みのプロパティの値は共有した人と同じになる / 却下案: 装備セットのレコードと同じ内容だけを共有する。共有した人の登録済みのユーザー定義プロパティも共有に含めて計算に使う（例外を持たない前の決定の文字どおりの適用））
- キャラクタースナップショットは、保存されているキャラクター全体（キャラクターの ID を除く）の複製とし、共有のジョブ・サポートジョブの計算に要る部分に絞らない（出典: この grill で決定: 計算に使う情報が増えたときに共有に含めるかを決め直す手間と、絞り込みの漏れでステータスが再現できなくなる危険を避けるため。公開される範囲は AC6 の文言で共有を作る前に知らせる / 却下案: 種族・メインジョブとサポートジョブのレベル・マスターレベル・スキル値・共通のメリットポイントと、その 2 ジョブ分のジョブ別メリットポイントとジョブポイントに絞る）
- 共有には、キャラクタースナップショットの中を含め、キャラクターの ID を入れない（出典: この grill で決定: 閲覧者は共有元のキャラクターを ID で指す操作をせず、インポートでは閲覧者自身のキャラクターを選び直すので、ID は閲覧者の側で使われない / 却下案: キャラクタースナップショットにキャラクターの ID も含める）
- 共有は装備セットとは別の、変更できない記録（共有の記録）として保存する。元の装備セットのレコードに公開の印を付ける方式は採らない（出典: [ADR 0008](../adr/0008-equipset-sharing.md)）
- 共有の記録を作れるのはログインしている人だけで、削除できるのは作った人だけである。未ログインを含む全員による閲覧は、共有 ID を引数に 1 件だけを返すサーバー側の関数（`get_shared_equipset`）だけを通し、この関数は作った人のアカウントの識別子（`user_id`）を返さない。テーブルを直接読めるのは、作った人が自分の記録を読むときだけである（出典: この grill で決定: SELECT を `using (true)` にすると共有 ID で絞らない全件の取得が通り、共有 URL を知らない人にもキャラクターの内容とアカウントの結び付きが読めて、AC6 の文言「共有 URL を知っている人は誰でも」が偽になるため / 却下案: SELECT を `using (true)` にして共有 ID（UUID）の推測しにくさだけに頼る（[ADR 0008](../adr/0008-equipset-sharing.md) を改訂する）。仕組みは変えず、AC6 の文言を誰でも一覧で取得できる公開データになる旨に改める）
- 共有の内容が URL を知る全員に公開されることは、共有を作る前に画面で知らせる（出典: [ADR 0008](../adr/0008-equipset-sharing.md) は公開範囲の明示を UI の責務とし、フォローアップ候補に挙げている）
- 共有 URL に装備セットの中身を埋め込まず、共有 ID だけを載せる（出典: [ADR 0008](../adr/0008-equipset-sharing.md)）
- 装備セットの名前・キャラクター名・ジョブはレコードの列に、スロットなどそれ以外はレコードの JSON に入れ、キャラクタースナップショットは JSON の `character` に入れる（出典: [ADR 0008](../adr/0008-equipset-sharing.md)）
- 閲覧者はキャラクタースナップショットをステータスの計算にだけ使い、閲覧者自身のデータを上書きしない。インポートでは閲覧者自身のキャラクターとジョブを選び直させる（出典: [ADR 0008](../adr/0008-equipset-sharing.md)）
- インポートはログインを前提としない。ログインを求めるのは共有の作成だけである（出典: [ADR 0005](../adr/0005-localstorage-default-supabase-optin.md) の「未ログインで全機能が使える」（ADR 0008 がログインを求める共有の作成を除く）、[ADR 0008](../adr/0008-equipset-sharing.md) がログインを求めるのは作成だけ）
- 共有閲覧モードではサイドバーを描画しない。CSS で隠すのではなく、描画しない分岐にする（出典: [ADR 0013](../adr/0013-sidebar-spa-mantine.md)）
- 共有閲覧モードの装備選択モーダルは、編集 UI を描画しない読み取り専用の分岐で描画する（出典: [ADR 0014](../adr/0014-equipset-grid-modal.md)）
- 共有の内容はフィールドを明示して組み立てる。共有閲覧モードではステータスビューの選択を記憶しない（出典: [ADR 0015](../adr/0015-property-sets.md)）
- 装備セットに保存したステータスビューの選択は、テンプレートを指すときだけ共有に含め、共有閲覧モードはそのテンプレートで開く。カスタムステータスビューを指すときは含めず、「待機/防御/回避」で開く（出典: この grill で決定: WS 用の装備セットのように、見せたいテンプレートと組で意味を持つ装備セットがあり、閲覧者がテンプレートを選び直す手間を省くため。カスタムステータスビューは共有した人の保存先にしか無く、閲覧者の側では表示できないので含めない / 却下案: ステータスビューの選択を共有に含めない（前の決定。[ADR 0015](../adr/0015-property-sets.md)・[ADR 0008](../adr/0008-equipset-sharing.md) を改訂した））
- 内訳モーダルは読み取り専用の機能なので、共有閲覧モードでも開ける（出典: この grill で決定: S3（ステータスの内訳まで確かめたい）のため / 却下案: 共有閲覧モードでは内訳を開けない）
- 共有の読み込みに失敗したときの共有ヘッダは固定の日本語の文言だけを出し、失敗の理由の文字列を出さない（出典: この grill で決定: サーバーやブラウザが返す理由は英語の内部メッセージ（共有が無いときの `shared equipset not found` や、Supabase・fetch のエラーの文字列）で、閲覧者には意味が読めないため / 却下案: 失敗の理由の文字列をそのまま出す（今の実装））

## 設計上の論点

- **D1**: 共有を利用者が後から一覧・削除する手段をどう用意するか（ADR 0008 のフォローアップ候補。削除の権限は既にある）。D1 で利用者が削除する手段を用意したときは、AC6 の文言「発行した共有は取り消せません。」を直す。
- **D2**: 共有の記録が増え続けることへの対処（期限・上限・GC）を持つか。AC9（発行するたびに新しい共有を作る）もこの記録の数に効く。
- **D3**: 共有を、元の装備セット・キャラクターの更新に追従させるか。今は追従させず、発行するたびに新しい共有を作る（AC1・AC9）。GitHub issue #67 で決める。
- **D4**: 共有に装備セットの ID（→ 0006）を含めるか。0006 で装備セットに不変の ID を付けた（0006 の AC75）ことで生まれた問い。今の AC2 の 7 つには含まれない。キャラクターの ID は含めないと決めている（制約 3 行目）。
