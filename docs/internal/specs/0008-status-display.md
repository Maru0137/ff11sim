# ステータスの表示

この仕様書の用語は [用語集](../../../CONTEXT.md) と、依存する仕様書（[0006 装備セットの編集](0006-equipset-editing.md)、[0002 キャラクターの管理](0002-character-management.md)、[0003 ステータスビューの管理](0003-status-view-management.md)、[0001 保存と同期](0001-saving-and-sync.md)、[0007 ステータスの計算](0007-status-calculation.md)）の用語節に従う。この仕様書で定義する語は「用語」節に書く。

## 用語

**ステータス欄**:
装備セット画面（→ 0006）で装備グリッドの隣に置かれ、選んでいるキャラクター（→ 0002）・ジョブ・サポートジョブ（→ 0006）・装備セットのステータスを表示する領域。
次のものからなる: 見出し「ステータス」とその横の「内訳」ボタン、常時表示ビュー（→ 0003）、ステータスビューの選択（→ 0006）を変えるステータスビューの選択欄とその右に並ぶボタン（「⚙ プロパティセット管理」「✎ このセットを編集」「内訳」。UI 上の表示）、選択中のステータスビュー 1 つの表示。

**ステータスビューの選択欄**:
ステータス欄の中で、ステータスビューの選択を変えるためのドロップダウン。UI 上の見出しは「プロパティセット:」。
修飾の無い「選択欄」は、キャラクター・ジョブなどを選ぶ欄にも使う一般名詞なので、この語の意味では使わない。

**内訳モーダル**:
内訳（→ 0007）を表で示すモーダル。行が寄与元行で、最後に合計の行を持つ。列は、先頭に寄与元行の名前の列と補足の列（2 列目）があり、その後にプロパティの列が続く。
対象によって 2 つのモードがある。
- ステータスの内訳: 常時表示ビューの 2 枚の表にある 17 項目を列にする
- ステータスビューの内訳: 選択中のステータスビューに表示されるプロパティのうち、内訳を求めるプロパティ（→ [0007-status-calculation.md](0007-status-calculation.md) の AC39）を列にする。テンプレートでは、その表に表示されるセル 1 つを 1 列にする

**寄与元行**:
内訳モーダルの行のうち、合計の行を除いたもの。寄与元（→ 0007）1 つにつき 1 行で、装備の 16 スロットの行と、キャラクター由来の 8 行（基礎・種族・メイン・サポ・メリポ・JP・ギフト・ML。UI 上の表示名）からなる。

## 課題

- **P1**: 利用者が、装備セットを組み替えたときにキャラクターのステータスがどう変わるかを、装備を変えながらその場で確かめられない。
- **P2**: 利用者が気にするプロパティは用途（待機・オートアタック・ウェポンスキル・魔法の種類など）によって違い、全部を一度に並べると目的の値を探せない。
- **P3**: 利用者が、表示された合計値がどの装備・どの育成要素から来ているかを確かめられず、値の検算や装備の入れ替え候補の判断ができない。
- **P4**: 利用者が、装備セットごとに見たいステータスビューを毎回選び直す手間がかかる。

## ユーザーストーリー

- **S1**: 利用者として、編集中の装備セットとキャラクターから求めたステータスを、装備グリッドの隣で見たい（→ P1）
- **S2**: 利用者として、表示するステータスビューを用途に合わせて選び替えたい（→ P2）
- **S3**: 利用者として、装備セットごとに最後に保存したときのステータスビューの選択が、次にその装備セットを開いたときに復元されてほしい（→ P4）
- **S4**: 利用者として、ステータスの値を寄与元ごとに分けた内訳を見たい（→ P3）

## ユーザージャーニー

### J1: 装備を変えながらステータスを確かめる（→ S1）

1. 利用者は装備セット画面でキャラクター・ジョブ・装備セットを選ぶ（選ぶ操作は → [0006-equipset-editing.md](0006-equipset-editing.md)）
2. ステータス欄に常時表示ビューと選択中のステータスビューが表示される
3. 利用者がスロットの装備やサポートジョブを変えると、ステータス欄の値が変わる

### J2: ステータスビューを選び替える（→ S2, S3）

1. 利用者はステータス欄のステータスビューの選択欄を開く
2. ステータスビューの選択欄にはテンプレートがグループごとに並び、カスタムステータスビューがあれば「カスタム」グループに並ぶ
3. 利用者が 1 つを選ぶと、ステータスビューの選択欄の下の表示がそのステータスビューに切り替わる
4. 利用者が装備セットを保存すると、ステータスビューの選択がその装備セットと一緒に保存される（保存の振る舞いは → [0006-equipset-editing.md](0006-equipset-editing.md)）
5. 後でその装備セットを開くと、保存したステータスビューの選択が復元される
6. 利用者が、選んでいるカスタムステータスビューを管理画面（→ [0003-status-view-management.md](0003-status-view-management.md)）で削除すると、選択は既定のテンプレートに戻る

### J3: 内訳を確かめる（→ S4）

1. 利用者はステータス欄の「内訳」ボタンを押す。見出し「ステータス」の横のボタンはステータスの内訳、ステータスビューの選択欄の右のボタンはステータスビューの内訳を開く
2. 内訳モーダルが開き、寄与元行と合計の行からなる表が表示される
3. 利用者は必要なら「値のない行を隠す」で、値の無い寄与元行を隠す
4. 利用者はモーダルを閉じて編集に戻る

## 受け入れ基準

### 全体

- **AC1**: ステータスが求まらないとき（どの場合に求まらないかは → [0007-status-calculation.md](0007-status-calculation.md) の AC3）、常時表示ビューとテンプレートの表の値のセルと、カスタムステータスビューの各組の値はすべて「-」と表示され、2 つの「内訳」ボタンは表示されない。有効スキル値の一覧は見出しだけを表示し、スキルの行も AC8 の「(表示できるスキルなし)」も表示しない。プロパティを 1 つも含まないカスタムステータスビューを選んでいるときは、AC16 の文言を表示する。
- **AC2**: 値が 0 または値が無いプロパティ（値が求まらないプロパティ（→ [0007-status-calculation.md](0007-status-calculation.md) の AC40）を含む）は、テンプレートとカスタムステータスビューの表示で「-」と表示される。
- **AC41**: テンプレートとカスタムステータスビューの表示で、0 でない値の表示の形（例: 数のまま、「N%」）は、プロパティごとに [0003-status-view-management.md](0003-status-view-management.md) の AC55 が定める形に従う。AC32 により、内訳モーダルの合計の行も同じ形になる。

### J1: 装備を変えながらステータスを確かめる

- **AC3**（手順2）: ステータス欄は上から、見出し「ステータス」、常時表示ビューの 2 枚の表、ステータスビューの選択欄、選択中のステータスビューの表示、常時表示ビューの有効スキル値の一覧の順に並ぶ。常時表示ビューの中身（行・列とその順）は → [0003-status-view-management.md](0003-status-view-management.md)。
- **AC4**（手順2）: 常時表示ビューの 1 枚目の表（行は → [0003-status-view-management.md](0003-status-view-management.md) の AC4）の「素」列と「合計」列は整数で表示され、値が 0 なら「0」と表示される。「装備」列は正の値なら「+N」、負の値なら「-N」、0 なら「-」と表示される。「BP からの換算」列と「スキルからの換算」列は、この表では値が空（→ [0007-status-calculation.md](0007-status-calculation.md) の AC12）なので、常に「-」と表示される。各列の値の意味は → [0007-status-calculation.md](0007-status-calculation.md)。
- **AC5**（手順2）: 常時表示ビューの 2 枚目の表（行は → [0003-status-view-management.md](0003-status-view-management.md) の AC4）のうち、ヘイスト・被ダメージ-・被物理ダメージ-・被魔法ダメージ- の 4 行（UI 上の表示名）は、「素」「BP からの換算」「スキルからの換算」の 3 列が値が空（→ [0007-status-calculation.md](0007-status-calculation.md) の AC14）なので常に「-」で、「装備」列と「合計」列は同じ値を「N%」の形で表示する（0 なら「-」）。
- **AC39**（手順2）: 常時表示ビューの 2 枚目の表のうち、防御力・回避・魔防・魔回避の 4 行（UI 上の表示名）は、5 列すべてを整数で表示し、値が 0 なら「0」と表示する。式に BP から求まる項が無いときの「BP からの換算」と、有効スキル値から求まる項が無いときの「スキルからの換算」は値が 0（→ [0007-status-calculation.md](0007-status-calculation.md) の AC13）なので「0」と表示する。負の値は「-N」と表示し、「装備」列の正の値にも「+」を付けない。
- **AC6**（手順2）: 被ダメージ-・被物理ダメージ-・被魔法ダメージ- の 3 行は、装備から拾った値の符号を反転して表示する。被ダメージを 30% 減らす装備の合計は「30%」、被ダメージを増やす装備は負の値で表示される。
- **AC7**（手順2）: 有効スキル値の一覧の見出しは「有効スキル値（スキル値とこのジョブのスキル上限の小さい方に、メリットポイント・装備・ギフトのボーナスを足した値）」（UI 上の表示）である。一覧は各スキルを「スキル名: 値」の形で表示し、メインスロットの武器のスキルには「(主武器)」が付く。メインスロットに武器が無いときは、どのスキルにも「(主武器)」を付けない。「(主武器)」の付いたスキルの値も有効スキル値であり、メインスロットのスロット専用のスキルボーナス（→ [0007-status-calculation.md](0007-status-calculation.md)）は含まない（有効スキル値の定義は → [0007-status-calculation.md](0007-status-calculation.md)）。
- **AC8**（手順2）: 有効スキル値の一覧に出すスキルが 1 つも無いとき、一覧は「(表示できるスキルなし)」と表示する。
- **AC9**（手順1・3）: ステータスが計算し直されたとき（いつ計算し直すかは → [0007-status-calculation.md](0007-status-calculation.md) の AC42）、ステータス欄は保存の操作なしに新しい値を表示する。

### J2: ステータスビューを選び替える

- **AC37**（手順1）: ステータスビューの選択欄は見出し「プロパティセット:」の右に置かれ、閉じているときは選択中のテンプレート名またはカスタムステータスビュー名を表示する。ステータスビューの選択欄の右には、「⚙ プロパティセット管理」「✎ このセットを編集」「内訳」（UI 上の表示）のボタンがこの順に並ぶ（「プロパティセット管理」と「このセットを編集」の出る条件は → [0003-status-view-management.md](0003-status-view-management.md)、「内訳」の出る条件は AC21）。ステータスビューの選択欄は、ステータスが求まらないとき（AC1）も表示され、開いて選び替えられる。
- **AC10**（手順2）: ステータスビューの選択欄の先頭から、すべてのテンプレートが、[0003-status-view-management.md](0003-status-view-management.md) の AC1 のグループと順で、グループごとに分かれて並ぶ。
- **AC11**（手順2）: カスタムステータスビューが 1 つ以上あるとき、ステータスビューの選択欄の末尾に「カスタム」グループが表示され、利用者のすべてのカスタムステータスビューが保存先に加わった順（新しく加わったものが末尾。[0003-status-view-management.md](0003-status-view-management.md) の AC30 の管理画面の一覧と同じ順）に並ぶ。1 つも無いとき「カスタム」グループは表示されない。
- **AC12**（手順3）: テンプレートを選ぶと、そのテンプレートが定める表（行・列の出し分けを含む。→ [0003-status-view-management.md](0003-status-view-management.md)）がステータス欄に表示される。
- **AC13**（手順3）: カスタムステータスビューを選ぶと、そのカスタムステータスビューのプロパティが、表示するプロパティの列（→ 0003）の順に、プロパティ名と値の組の並びとして表示される。
- **AC14**（手順3）: カスタムステータスビューの表示で、ユーザー定義プロパティはプロパティ名を登録した名前で表示し、マウスを重ねると「ユーザー定義項目 (装備説明文から抽出)」（UI 上の表示）と示される。
- **AC15**（手順3）: カスタムステータスビューが、組み込みプロパティにも登録済みのユーザー定義プロパティにも当たらない識別子を含むとき、その組は識別子の文字列をプロパティ名とし、値を「-」として薄い色で表示する。
- **AC16**（手順3）: プロパティを 1 つも含まないカスタムステータスビューを選ぶと、「項目がありません。「プロパティセット管理」から編集してください。」（UI 上の表示）と表示される。
- **AC17**（手順4・5）: 装備セットを保存した後にその装備セットを開き直すと、保存したときのステータスビューの選択が選ばれている。
- **AC18**（手順5）: 保存せずに選択を変えた後、未保存の確認ダイアログ（→ [0006-equipset-editing.md](0006-equipset-editing.md)）で「破棄して続行」を選んで別の装備セットに切り替えた後、またはページを離れることを承認して再読み込みした後に、その装備セットを開き直すと、変えた選択は残らず、最後に保存した選択（保存した選択が無ければ AC19 の既定）が選ばれる。
- **AC19**（手順5）: 選択を一度も保存していない装備セット、新しく作り始めた装備セット、保存した選択のテンプレートまたはカスタムステータスビューが存在しない装備セット（削除したカスタムステータスビューを選んで保存していた装備セットと、別のタブ・別の端末で削除されたカスタムステータスビューを選んで保存していた装備セットを含む）を開くと、既定として「待機/防御/回避」テンプレートが選ばれる（テンプレート名は → [0003-status-view-management.md](0003-status-view-management.md) の AC1）。
- **AC20**（手順6）: この画面の管理画面（→ [0003-status-view-management.md](0003-status-view-management.md)）で、選んでいるカスタムステータスビューを削除すると、選択は「待機/防御/回避」テンプレートに戻る。別のタブ・別の端末で削除されたときは、その装備セットを開き直したときに AC19 の既定が選ばれる。
- **AC40**（手順5・6）: AC19・AC20 で選択を既定に置き換えても、未保存の変更（→ [0006-equipset-editing.md](0006-equipset-editing.md) の AC52）にはならず、置き換えた直後に別の装備セットに切り替えても未保存の確認ダイアログは出ない。置き換えは装備セットのステータスビューの選択（→ 0006）を変えず、利用者がステータスビューの選択欄で選び直すまで、装備セットを保存したときに書かれる選択は置き換える前の値のままである。

### J3: 内訳を確かめる

- **AC21**（手順1）: 2 つの「内訳」ボタンは、ステータス欄に値が表示されているときだけ表示される（AC1 の場合は表示されない）。
- **AC22**（手順2）: ステータスの内訳の題は「内訳: ステータス」、ステータスビューの内訳の題は「内訳: <選択中のテンプレート名またはカスタムステータスビュー名>」である。
- **AC23**（手順2）: ステータスの内訳の列は、HP・MP・STR・DEX・VIT・AGI・INT・MND・CHR・ヘイスト・防御力・回避・魔防・魔回避・被ダメージ-・被物理ダメージ-・被魔法ダメージ- の 17 列で、この順に並ぶ（UI 上の表示名）。列名は常時表示ビューの行名（→ [0003-status-view-management.md](0003-status-view-management.md) の AC4）と同じである。
- **AC24**（手順2）: カスタムステータスビューを選んでいるときのステータスビューの内訳の列は、そのカスタムステータスビューのプロパティのうち内訳を求めるプロパティ（→ [0007-status-calculation.md](0007-status-calculation.md) の AC39）を、表示するプロパティの列の順に並べたものである。ユーザー定義プロパティは列に含まれる。列名は、ステータス欄のカスタムステータスビューの表示と同じプロパティ名（組み込みプロパティは表示名、ユーザー定義プロパティは登録した名前）である。AC15 の、どのプロパティにも当たらない識別子は列に含めない。
- **AC25**（手順2）: テンプレートを選んでいるときのステータスビューの内訳の列は、そのときステータス欄に表示されているテンプレートの表のセル（表示条件で隠れた表・行・列のセルを除く）のうち、内訳を求めるプロパティ（→ [0007-status-calculation.md](0007-status-calculation.md) の AC39）のセルすべてである。基本ステータス（例: 魔法系テンプレートの INT・MND・CHR・MP）のセルも列に含まれる。セル 1 つが 1 列になり、表の順、各表の中では上の行から、行の中では左の列からの順に並ぶ。行見出し（メイン・サブ・レンジ）のある表のセルの列名は「<行見出し> <列見出し>」（例: 「メイン 命中」）、行見出しの無い表のセルの列名は列見出しである。AC25 は目標の振る舞いで、今の実装はこれを満たさない（GitHub issue #66、D1）。
- **AC26**（手順2）: プロパティの列が 1 つも無いとき、モーダルは「内訳を表示できる項目がありません」と表示する。
- **AC27**（手順2）: 寄与元行は、装備の 16 スロット（メイン・サブ・レンジ・矢弾・頭・胴・両手・両脚・両足・首・腰・左耳・右耳・左指・右指・背）の行、続いて基礎・種族・メイン・サポ・メリポ・JP・ギフト・ML の 8 行の順に並ぶ。
- **AC28**（手順2）: 装備のスロットの行は、2 列目にそのスロットの装備の日本語名（日本語名が無ければ英語名）を表示し、オーグメントのランクを選んでいるときは名前の後に「 R<ランク>」を付ける。そのスロットに装備が無いときは 2 列目が空になる。
- **AC29**（手順2）: キャラクター由来の行の 2 列目は次のとおり表示する。基礎: 「Lv・ステータス・スキル由来」/ 種族: 種族名 / メイン: 「<ジョブ名><レベル> (ジョブ+特性)」/ サポ: サポートジョブがあれば「<ジョブ名><サポートジョブの有効レベル> (ジョブ+特性)」、無ければ空 / ML: マスターレベルが 1 以上なら「ML<マスターレベル>」、0 なら空 / それ以外の行: 空。
- **AC30**（手順2）: 寄与元行の値が 0 または値が無いセルは「-」と表示される。負の値は負の値のまま表示され、正の値のセルと異なる文字色で表示される。
- **AC31**（手順2）: 種族・メインジョブ（表示名「メイン」）・サポートジョブ（表示名「サポ」）の行の基本ステータスの列は、小数を切り捨てずに、小数第 3 位を四捨五入して小数第 2 位までで表示し、末尾の 0 と小数点は省く（例: 37.5、45、13.25）。
- **AC32**（手順2）: 合計の行の各セルは、ステータス欄でその列に対応するセル（ステータスの内訳では常時表示ビューのその行の「合計」列のセル、カスタムステータスビューでは同じプロパティ、テンプレートでは同じセル）の表示値と同じ文字列である。
- **AC42**（手順2）: ステータスの内訳の被ダメージ-・被物理ダメージ-・被魔法ダメージ- の列では、寄与元行は装備から拾った値の符号を反転した数を「%」を付けずに表示し、AC30 の負の値の文字色は反転した後の値で判定する。合計の行は AC32 のとおりステータス欄の「N%」の文字列である。ヘイストの列では、寄与元行は符号を反転せず「%」を付けずに表示し、合計の行は AC32 のとおりである。
- **AC43**（手順2）: 武器のスキル値が求まらないとき（→ [0007-status-calculation.md](0007-status-calculation.md) の AC26・AC36）、その武器のスキル値の列の寄与元行のセルはすべて「-」と表示され、合計の行は AC32 のとおりステータス欄の対応するセルと同じ「-」である。
- **AC33**（手順2）: 表の下に注記が表示される。どのモードでも、ジョブ特性の注記（ジョブ特性の寄与はメインジョブとサポートジョブのうちランクの高い側の行に表示する、という内容を含む）が表示される。ステータスの内訳では、加えて次の 2 つが表示される。
  - 基本ステータスの小数の注記: 種族・メインジョブ・サポートジョブの基本ステータスの寄与は小数を持ち、合算してから切り捨てる、という内容を含む
  - 基礎行の注記: 「基礎」の行はレベル・基本ステータス・スキル値から求まる項である、という内容と、その例を 1 つ以上含む

  ステータスビューの内訳では、加えて次の 3 つが表示される。ステータスビューの内訳に基本ステータスの列があるときは、基本ステータスの小数の注記も表示される。
  - 基礎行の注記: 「基礎」の行はレベル・基本ステータス・スキル値から求まる項である、という内容と、その例を 1 つ以上含む
  - スキル値の列の帰属の注記: スキル値の列では、「基礎」の行はマスターレベルを 0 としたスキル上限までのキャラクターのスキル値、「ML」の行はマスターレベルで広がったスキル上限による増分、「メリポ」の行はスキルのメリットポイントの分である、という内容を含む（帰属の規則は → [0007-status-calculation.md](0007-status-calculation.md) の AC35）
  - 除外の注記: 内訳を求めないプロパティ（→ [0007-status-calculation.md](0007-status-calculation.md) の AC39）は列に含まれない、という内容を含む
- **AC34**（手順2）: 内訳を計算している間は「計算中...」、計算できなかったときは「内訳を計算できませんでした」と表示される。
- **AC35**（手順3）: 「値のない行を隠す」に印を付けると、すべてのプロパティの列のセルが「-」の寄与元行が隠れる（2 列目の補足は判定に含めない）。印を外すと再び表示される。合計の行は常に表示される。
- **AC36**（手順2）: 画面の幅が 768px 以下のとき、内訳モーダルは画面全体に表示される。
- **AC38**（手順4）: 内訳モーダルは、右上の閉じるボタン、Esc キー、モーダルの外側のクリック（画面の幅が 768px を超えるとき）のどれでも閉じる。閉じた後のステータスビューの選択は、モーダルを開く前と同じである。閉じた後のステータス欄の表示は、そのときの計算の入力から求めた値である（モーダルを開いている間に計算の入力が変わったときは、変わった後の値。→ [0007-status-calculation.md](0007-status-calculation.md) の AC42）。次に内訳モーダルを開いたとき、「値のない行を隠す」の印は外れている。

## 制約

- ステータスビューの選択はドロップダウンで行い、テンプレートとカスタムステータスビューをグループで分ける（出典: [ADR 0015](../adr/0015-property-sets.md)）
- 種族・メイン・サポの基本ステータスの寄与は小数のまま表示し、合算後に切り捨てる旨を注記する（出典: [ADR 0016](../adr/0016-status-breakdown-modal.md)）
- 内訳の合計の行はステータス欄の表示値をそのまま参照する（出典: [ADR 0016](../adr/0016-status-breakdown-modal.md)）
- モーダルは Mantine の Modal で作り、開閉は呼び出し側のローカル状態で持つ（出典: [ADR 0014](../adr/0014-equipset-grid-modal.md)）

## 設計上の論点

- **D1**: テンプレートを選んだときのステータスビューの内訳の列（AC25）を、テンプレートの宣言的な定義（表・行・列とセルのプロパティ。→ [0003-status-view-management.md](0003-status-view-management.md) の制約）から組み立てるか、テンプレートごとに列の並びを別に持つか。今はテンプレートを組み込みプロパティの平らな並びに変換した結果から列を作っており、基本ステータスと行の区別が落ちる（GitHub issue #66）。
