# 装備セットの編集

この仕様書の用語は [用語集](../../../CONTEXT.md) と、依存する仕様書（[0002 キャラクターの管理](0002-character-management.md)、[0005 装備検索](0005-item-search.md)、[0004 装備の解釈](0004-equip-interpretation.md)、[0003 ステータスビューの管理](0003-status-view-management.md)、[0001 保存と同期](0001-saving-and-sync.md)）の用語節に従う。この仕様書で定義する語は「用語」節に書く。

## 用語

**装備セット**:
あるキャラクターのあるジョブに属し、名前を付けた、スロットごとの装備の組。装備セットの ID で同じものとみなし、名前を変えても同じ装備セットのままである。同じキャラクターとジョブの中で名前は重複しない（AC1）が、名前は同じものかどうかの判定には使わない。保存・同期・共有（→ [0009 装備セットの共有](0009-equipset-sharing.md)）の単位。

装備セットが持つものは、装備セットの ID・キャラクター・ジョブ・名前・16 スロットの装備（アイテム・選んだオーグメント・カスタム説明）・ステータスビューの選択である。
キャラクターは、キャラクターの名前ではなく、キャラクターを作った時点に振られる変わらない ID（→ 0002）で指す。そのため、キャラクターの名前を変えても、装備セットはそのキャラクターに属したままである。
同じキャラクターとジョブの装備セットの間には並び順がある。サポートジョブは装備セットに含まれない。

**装備セットの ID**:
装備セットを作った時点で端末側で振られ（AC75）、その後変わらない識別子。端末内データとアカウントデータのどちらにあるかによらず、すべての保存先を通じて一意である。装備セットが同じものかどうか、装備セットの競合の単位（→ 0001）、保存先での識別キーは、この ID で決まる。ID は利用者が入力・編集するものではない。

**装備セット画面**:
サイドバーの「装備セット」（UI 上の表示）から開く、装備セットを選んで編集する画面。URL のハッシュは `#/equipsets`。
キャラクター・ジョブ・サポートジョブの選択欄、タブ、装備セットの編集フォームからなる。
_使わない_: 装備セットの画面、装備セットの編集画面、装備セットビュー

**サポートジョブ**:
装備セット画面で選ぶ、メインジョブ以外のジョブ 1 つ。選ばなくてもよい。ステータスの計算（→ [0007 ステータスの計算](0007-status-calculation.md)）の入力で、キャラクターにも装備セットにも保存されない（共有には含まれる → 0009）。

選ばないこと（UI 上の表示は「-- なし --」）は、サポートジョブが無い状態を表す。ゲームのサポートジョブ無効エリア（サポートジョブのレベルが 0 として扱われる場所）も「-- なし --」で表す。
選択肢と、ジョブを変えたときに未選択に戻ることは J1 の受け入れ基準（AC7〜AC10）にある。
サポートジョブを変えても未保存の変更にはならない（AC59）。計算にどのレベルを使うか（サポートジョブの有効レベル）は 0007 が定める。

**ステータスビューの選択**:
装備セットごとに記録する、ステータス欄（→ [0008 ステータスの表示](0008-status-display.md)）でどのステータスビューを表示するかの選択。テンプレート 1 つ、またはカスタムステータスビュー 1 つを指す。テンプレートを指すときは共有に含まれる（→ 0009）。
装備セットを保存したときだけ記録され、選び替えただけでは記録されない。

選択を変える操作と、記録した選択を装備セットを開いたときに復元する振る舞い（選択が指すステータスビューが存在しないとき・一度も記録されていないときの既定を含む）は 0008 が定める。
この仕様書は、ステータスビューの選択が装備セットに保存されること（AC3）と、未保存の変更の比較対象に入ること（AC52）を定める。

**装備グリッド**:
16 スロットを 4 行 4 列に並べ、各スロットの装備を表示する領域。表示専用で、スロットをクリックすると装備選択モーダルが開く。
並びは FF11 の装備画面と同じで、1 行目からメイン・サブ・レンジ・矢弾 / 頭・首・左耳・右耳 / 胴・両手・左指・右指 / 背・腰・両脚・両足。

**装備選択モーダル**:
1 つのスロットについて、装備の選択・オーグメントの選択・カスタム説明の入力・装備を外す操作をまとめて行うダイアログ。
上段に選択中の装備の詳細と編集欄、下段にアイテムの検索がある。

**装備セットの編集フォーム**:
装備セット画面のうち、装備セット 1 つを編集する領域。名前の入力欄、保存・複製・共有・削除のボタン、装備グリッド、ステータス欄（→ 0008）からなる。
_使わない_: 編集フォーム（修飾なし。キャラクターの編集フォーム（→ 0002）と区別するため）

**タブ**:
選択中のキャラクターとジョブに属する装備セット 1 つを表す、装備セットの編集フォームの上のボタン。押すとその装備セットを装備セットの編集フォームに読み込む。

**新規フォーム**:
「+」で開く、まだ保存していない装備セットの編集フォーム。名前は空で、16 スロットはすべて装備無し。

**既定のオーグメント**:
装備を選んだときに自動で選ばれるオーグメント。オーグメントの種類（経路）が 1 つだけのアイテムでは、その経路の最も高いランクになる。経路が 2 つ以上あるアイテムと、オーグメントのデータが無いアイテムでは、何も選ばれない。

## 課題

- **P1**: 利用者は、ジョブ・用途ごとの装備の組み合わせを何通りも作って比べたいが、毎回 16 スロットを選び直すのは手間がかかる。
- **P2**: 利用者は、装備を変えながらステータスがどう変わるかを確かめたいが、装備の表示とステータスの表示が画面の上下に離れているとスクロールの往復が要る。
- **P3**: 同じアイテムでもオーグメントのランクや個体差で性能が変わるため、アイテム説明文だけでは利用者の実際の装備を表せない。
- **P4**: 利用者は、保存し忘れたまま別の装備セットへ移って、編集内容を失うことがある。

## ユーザーストーリー

- **S1**: 利用者として、キャラクターとジョブ（必要ならサポートジョブ）を選んで、そのジョブの装備セットを一覧から選んで開きたい（→ P1）
- **S2**: 利用者として、装備セットを新しく作り、名前を付けて保存したい（→ P1）
- **S3**: 利用者として、16 スロットの装備をひと目で確認しながら、スロットごとに装備を選び直したい（→ P2）
- **S4**: 利用者として、スロットとジョブで絞り込まれた候補からアイテムを探して装備したい（→ P1、P2）
- **S5**: 利用者として、装備にオーグメントのランクを選び、オーグメントのデータが無い効果はカスタム説明に自分で書きたい（→ P3）
- **S6**: 利用者として、既存の装備セットを複製・名前の変更・削除・並べ替えしたい（→ P1）
- **S7**: 利用者として、保存していない変更があることが分かり、編集内容が失われる操作の前に保存するか捨てるかを選びたい（→ P4）

## ユーザージャーニー

### 全体の流れ

装備セット画面では、まずキャラクターとジョブを選ぶ（J1）。そのジョブに装備セットがあれば先頭のタブが開き、無ければ「+」から新規フォームを開く（J2）。
装備セットの編集フォームでは装備グリッドのスロットから装備選択モーダルを開いて装備を編集し（J3・J4）、保存する（J2）。
既存の装備セットには複製・削除・並べ替え（J5）ができる。どの段階でも、未保存の変更（→ 0001）があるまま編集内容が失われる操作をすると確認が入る（J6）。

### J1: 装備セットを開く（→ S1）

1. 利用者はキャラクターを選ぶ。
2. 利用者はジョブを選び、必要ならサポートジョブを選ぶ。
3. そのキャラクターとジョブの装備セットがタブとして並び、先頭の装備セットが装備セットの編集フォームに読み込まれる。
4. 利用者は別のタブを押して、その装備セットを読み込む。

インポート（→ 0009）の直後は、手順 1〜3 を経ずに、インポートした装備セットを開いた状態の装備セット画面に着く（AC15）。

### J2: 装備セットを作って保存する（→ S2、S6）

1. 利用者は「+」を押して新規フォームを開く。
2. 利用者は名前を入力し、装備を編集する（J3・J4）。
3. 利用者は「保存」を押す。
4. 装備セットが保存され、タブの末尾に加わって選ばれた状態になる。
5. 利用者は名前を書き換えて保存し、装備セットの名前を変える。

### J3: スロットの装備を選ぶ（→ S3、S4）

1. 利用者は装備グリッドのスロットを押す。
2. 装備選択モーダルが開き、そのスロットとジョブに合うアイテムの一覧が出る。
3. 利用者はキーワード（→ 0005）を入力して候補を絞り込み、必要ならページを送る・並べ替える・iLv119 絞り込み（→ 0005）を切り替える。
4. 利用者は一覧の行を押してアイテムを装備する。モーダルは開いたままで、上段に装備したアイテムが出る。
5. 利用者はモーダルを閉じる。装備グリッドのスロットにアイテムの名前と要約が出る。
6. 利用者は装備を外したいときは、モーダルの「装備を外す」を押す。

### J4: オーグメントとカスタム説明を設定する（→ S5）

1. 利用者は装備のあるスロットの装備選択モーダルを開く。
2. 利用者はオーグメントの選択肢から経路とランクを選ぶ。選んだオーグメントのオーグメント文が横に出る。
3. 利用者はカスタム説明の欄に効果を書く。書き方が分からないときは「?」で書き方を開く。
4. 利用者はモーダルを閉じる。装備グリッドのスロットに「Aug」「メモ」の印が出る。

### J5: 装備セットを複製・削除・並べ替えする（→ S6）

1. 利用者は保存済みの装備セットを開き、「複製」を押す。複製した装備セットがタブの末尾に加わって選ばれる。
2. 利用者は「削除」を押し、確認で了承する。装備セットが消え、残りの先頭のタブが読み込まれる。
3. 利用者はタブを別のタブの上へドラッグして落とし、並び順を変える。

### J6: 未保存の変更を扱う（→ S7）

1. 利用者が装備セットの編集フォームを編集すると、名前の横とタブに未保存の印が出て、「保存」が押せるようになる。
2. 利用者が編集内容の失われる操作（AC58 の 4 つの操作。例: 選択中でない別のタブを押す）をすると、未保存の確認ダイアログ（→ 0001）が出る。
3. 利用者は「保存して続行」「破棄して続行」「キャンセル」のどれかを選ぶ。

## 受け入れ基準

### 全体

- **AC1**: 装備セットは装備セットの ID で区別する。名前を変えて保存しても装備セットの ID は変わらず、同じ装備セットのままである。同じキャラクターとジョブの中で、同じ名前（AC18 の比べ方で同じ名前）の装備セットは 2 つ存在しない。キャラクターは ID（→ 0002）で指すので、キャラクターの名前を変えても、そのキャラクターの装備セットは同じタブの並びのまま、名前を変えたキャラクターを選んで開ける。
- **AC2**: 装備セットの編集フォームでの編集（装備・オーグメント・カスタム説明・名前・ステータスビューの選択）は、「保存」を押すか未保存の確認ダイアログで「保存して続行」を選ぶまで、保存済みの装備セットに反映されない。
- **AC3**: 保存・複製・削除・並べ替えの結果として保存されるものは、装備セットの ID・キャラクター・ジョブ・名前・16 スロットの装備（アイテム・選んだオーグメント・カスタム説明）・ステータスビューの選択と、同じキャラクターとジョブの中での装備セットの並び順である。サポートジョブの選択は保存されない。ログインしていない間は端末内データに、ログインしている間はアカウントデータに保存され、ログインしている間は同期される（→ 0001）。
- **AC4**: 初回アップロード（→ 0001）では、端末内データの装備セットをすべて、装備セットの ID・属するキャラクターの ID・ジョブ・名前・16 スロットの装備・ステータスビューの選択を保ってアカウントデータに加える。初回アップロードの時点でアカウントデータは空なので、同じキャラクターとジョブの中の並び順は端末内データでの並び順のままである。初回アップロードを行わない端末（そのアカウントで 2 台目以降にログインした端末）の装備セットはアカウントデータに送られず、端末内データに残る（→ 0001）。
- **AC5**: キャラクターを削除すると、そのキャラクターの装備セットもすべて削除される。削除の確認に出す文言（装備セットの件数と、装備セットの編集フォームの未保存の変更を示す行を含む）と、キャラクターの削除の保存の競合をそのキャラクターに属する装備セットの変更・追加・削除についても判定することは → 0002（AC53・AC61）。
- **AC74**: 装備セットの編集フォームでは、装備グリッドとステータス欄（→ 0008）を左右 2 列に並べる。画面の幅が 1100px 以下のときは縦に積む。装備グリッドは、ページをスクロールしている間も画面に表示されたまま残る。
- **AC76**: キャラクター画面（→ 0002）でジョブのレベルを 0 にしても、そのキャラクターのそのジョブの装備セットは削除されず、保存先に残る。レベル 0 の間はジョブの選択肢に出ない（AC8）ので開けないが、そのジョブのレベルを 1 以上に戻すと、再びジョブを選んで開ける。

### J1: 装備セットを開く

- **AC6**（手順1）: キャラクターの選択肢は、登録済みのキャラクターを「名前 (種族)」の形で並べたものと、未選択を表す「-- キャラクターを選択 --」である。
- **AC7**（手順1）: キャラクターを選んでいない間は、ジョブを選べない。キャラクターを未選択に戻すと、ジョブとサポートジョブも未選択に戻る。別のキャラクターに変えたとき、選んでいたジョブとサポートジョブのうち、新しいキャラクターでレベルが 1 以上のものは選んだまま残り、レベルが 0 のものだけが未選択（ジョブは「-- ジョブを選択 --」、サポートジョブは「-- なし --」）に戻る。ジョブだけがレベル 0 で未選択に戻ったときも、サポートジョブは新しいキャラクターでレベルが 1 以上なら選んだまま残る（AC9 は利用者がジョブを変えたときの規則で、この場合には当てはまらない）。
- **AC8**（手順2）: ジョブ（メインジョブ）の選択肢は、未選択を表す「-- ジョブを選択 --」と、選んでいるキャラクターでレベルが 1 以上のジョブである。レベルが 0 のジョブは選択肢に出ない。レベルが 0 のジョブの装備セットの扱いは AC76。
- **AC9**（手順2）: 選んでいたジョブを別のジョブに変えると、サポートジョブは未選択（「-- なし --」）に戻る。ジョブが未選択の状態からジョブを選んだときの規則は AC78。
- **AC10**（手順2）: サポートジョブの選択肢は、「-- なし --」と、選んでいるキャラクターでレベルが 1 以上のジョブのうちメインジョブ以外のものである。レベルが 0 のジョブとメインジョブと同じジョブは選択肢に出ない。
- **AC11**（手順3）: キャラクターとジョブの両方を選んだときだけ、タブと「+」が表示される。
- **AC12**（手順3）: キャラクターかジョブを変えると、新しい組の装備セットのうち並び順で先頭のものが装備セットの編集フォームに読み込まれる。新しい組に装備セットが 1 つも無いときは、装備セットの編集フォームが表示されない。
- **AC13**（手順4）: 選択中でないタブを押すと、押した時点で保存先から読み直したその装備セットの内容（名前・16 スロットの装備・ステータスビューの選択）が装備セットの編集フォームに読み込まれ、そのタブが選択中の表示になる。選択中のタブを押しても何も起きない（読み直さず、未保存の変更があっても未保存の確認ダイアログは出ない）。
- **AC14**（手順4）: 装備セットを読み込むと、開いていた装備選択モーダルは閉じる。
- **AC15**: インポート（→ 0009）に成功すると、装備セット画面が開き、キャラクターとジョブの選択欄はインポート先のキャラクターとジョブになり、インポートした装備セットが装備セットの編集フォームに読み込まれ、そのタブが選択中の表示になる。サポートジョブは未選択（「-- なし --」）である。
- **AC77**（手順2）: 装備セット画面で選んでいたジョブまたはサポートジョブのレベルが、キャラクター画面（→ 0002）で 0 にされたときは、装備セット画面に戻ったとき、レベルが 0 になったものが未選択（ジョブは「-- ジョブを選択 --」、サポートジョブは「-- なし --」）に戻る。レベルが 1 以上のままのものは選んだまま残る（AC7 と同じ規則）。ジョブが未選択に戻ったときは装備セットの編集フォームが閉じ、装備セットの編集フォームに未保存の変更があっても、未保存の確認ダイアログを出さずに捨てる（AC68 と同じ扱い）。
- **AC78**（手順2）: ジョブが未選択の間は、サポートジョブの選択欄を変えられない。サポートジョブを選んだまま残っている（AC7）ときも、その値は表示されたまま残る。ジョブが未選択の状態からジョブを選んだときは AC9 を当てはめず、サポートジョブは選んだまま残る。ただし、選んだジョブがサポートジョブと同じジョブのときは、サポートジョブが未選択（「-- なし --」）に戻る。
- **AC79**（手順1）: ページを読み込んだ（再読み込みを含む）後に初めて装備セット画面を開いたとき、キャラクター・ジョブ・サポートジョブの選択欄はどれも未選択（「-- キャラクターを選択 --」「-- ジョブを選択 --」「-- なし --」）である。ただし、インポートの直後は AC15 に従う。

### J2: 装備セットを作って保存する

- **AC16**（手順1）: 「+」を押すと、名前が空で 16 スロットがすべて「未設定」の新規フォームが開き、どのタブも選択中の表示にならない。新規フォームでは「削除」が表示されない。
- **AC17**（手順3）: 名前が空、または空白だけからなるまま「保存」を押すと、「装備セット名を入力してください。」と表示し、保存しない。
- **AC18**（手順3）: 保存の直前に保存先から読み直した、同じキャラクターとジョブの装備セットの一覧に、保存しようとしている装備セットとは別の装備セット（装備セットの ID が異なるもの）で同じ名前のものがあるときは、「装備セット「<名前>」は既に存在します。」と表示し、保存しない。名前が同じかどうかは、前後の空白を除いた後の完全一致で決める（大文字と小文字、全角と半角を区別する）。保存しようとしている装備セット自身の名前とは比べない。
- **AC19**（手順3）: 保存する名前は、入力の前後の空白を除いたものである。
- **AC20**（手順4）: 新規フォームで保存した装備セットは、そのキャラクターとジョブのタブの末尾に加わり、選択中のタブになる。
- **AC21**（手順5）: 既存の装備セットの名前を変えて保存すると、装備セットの ID とタブの位置は変わらず、タブの表示名が新しい名前になる。元の名前の装備セットは残らない。
- **AC22**（手順4）: 保存した後は未保存の変更が無い状態になる。
- **AC23**（手順3）: 保存は、開いている装備セット 1 つだけを書き換える。保存の直前に保存先（端末内データまたはアカウントデータ）を読み直し、他の装備セットは読み直した内容のまま残す。装備セットの競合の単位（→ 0001）は装備セット 1 つ（装備セットの ID で同じものとみなす）で、保存の競合（→ 0001）はこの単位で判定する。保存先から読み直したその装備セットの内容が、装備セットの編集フォームに読み込んだ（またはこの画面で最後に保存した）時点の内容と異なるときは、書き込む前に競合の警告（→ 0001 AC40）を出す。別の画面で名前だけを変えて保存されていたときも、内容が異なるので競合の警告を出す。
- **AC24**（手順3）: 保存の直前に読み直したとき、開いている装備セットが保存先から消えていたら（別の画面で削除されたときを含む）、保存せずに、その装備セットが保存先から消えていることを知らせ、「新しい装備セットとして保存」「破棄」「キャンセル」から選ばせる（知らせる表示の形と文言は D3）。
  - 「新しい装備セットとして保存」: 新しい装備セットの ID を振り、装備セットの編集フォームの内容をその装備セットとして、保存の直前に読み直した同じキャラクターとジョブの一覧の末尾に保存し、そのタブを選択中のタブにする。AC17・AC18 の規則はこの保存にも当てはまる。
  - 「破棄」: 何も保存せず、装備セットの編集フォームの編集内容を捨てる。消えていた装備セットはタブから除かれ、AC48 と同じく残りの装備セットのうち並び順で先頭のものが読み込まれる（残りが無いときは装備セットの編集フォームが表示されない）。
  - 「キャンセル」: 何も保存せず、装備セットの編集フォームの内容と未保存の変更をそのまま残す。
- **AC25**（手順3）: 保存に失敗したときは、失敗を通知し、装備セットの編集フォームの内容と未保存の変更をそのまま残す（通知の共通の振る舞いは → 0001）。
- **AC71**（手順2）: 新規フォームの未保存の変更は、名前が空で 16 スロットがすべて装備無しで、ステータスビューの選択が新規フォームを開いた時点の選択である内容と比べて決める（AC52）。新規フォームでステータスビューの選択だけを変えたときも、未保存の変更がある状態になる。新規フォームで名前を入力するか装備を編集すると、未保存の変更がある状態になり、「保存」が押せるようになる（AC54）。
- **AC75**（手順1・4）: 装備セットの ID は、新規フォームを開いた時点で、すべての保存先を通じて他のどの装備セットとも異なるものが振られ、新規フォームで保存した装備セットはその ID を持つ。保存に失敗して保存し直したときも、同じ ID で保存される。複製（AC45）、インポート（→ 0009）、AC24 の「新しい装備セットとして保存」では、保存する装備セットに新しい装備セットの ID が振られる。

### J3: スロットの装備を選ぶ

- **AC26**（手順1）: 装備グリッドの各スロットは、装備が無ければスロットの表示名・「未設定」・「クリックして選択」を表示する。
- **AC27**（手順1・5）: 装備グリッドの各スロットは、装備があればスロットの表示名・アイテムの日本語名（日本語名が無ければ英語名）・要約を表示する。要約は、アイテム説明文・オーグメント文・カスタム説明をこの順に改行を空白にして 1 行につなげたものである。要約の全文は、スロットにポインタを重ねると出る。
- **AC28**（手順2）: 装備選択モーダルの題は「<スロットの表示名> の装備」である。画面の幅が 768px 以下のときは画面全体に表示する。
- **AC29**（手順2）: 開いた直後の一覧は、キーワードなしで、そのスロットに装備でき、かつ選択中のジョブが装備できるアイテムを出す。左耳のスロットでは右耳用のアイテムも、左指のスロットでは右指用のアイテムも候補に入る。
- **AC30**（手順2・3）: メイン・サブ・レンジ・頭・胴・両手・両脚・両足のスロットでは iLv119 絞り込み（→ 0005。UI 上の表示は装備検索と同じ「iLv119のみ」）が表示され、開いた直後は有効である。有効な間は、iLv が 119 のアイテムだけが一覧に出る。その他のスロットでは「iLv119のみ」は表示されず、iLv で絞り込まない。「iLv119のみ」を切り替えると、一覧は 1 ページ目に戻る。
- **AC31**（手順2・3）: 一覧の件数の表示は装備検索の 0005 AC8 と、ページ送り（1 ページ 50 件、ページ送りの部品、ページ送りで使う検索条件）は 0005 AC34〜AC36 と同じである。該当するアイテムが無いときは「該当する装備がありません」と表示する。
- **AC32**（手順3）: キーワードの入力欄の内容を変えるたびに検索し、0005 AC10 の 4 つの名前の欄のどれかに 0005 AC11 の置き換えをした上でキーワードを含むアイテムへ一覧が絞り込まれ、1 ページ目に戻る。
- **AC33**（手順2・3）: 開いた直後の一覧は、アイテムの id の降順（新しいアイテムが上）に並ぶ。一覧の並べ替えは、名前・Lv・iLv の列見出しを押して行う。同じ列をもう一度押すと昇順と降順が入れ替わり、別の列を押すとその列の昇順になる。列見出しを押して並べ替えると、一覧は 1 ページ目に戻る。列見出しを押した後の並び順は 0005 AC27〜AC29 に従う。
- **AC34**（手順3）: 画面の幅が 768px を超えるとき、モーダルを開くとキーワードの入力欄に入力位置が置かれる。768px 以下のときは置かれない。
- **AC35**（手順4）: 一覧で、そのスロットに装備が無いとき、または装備しているアイテムとは別のアイテムの行を押すと、そのスロットの装備がそのアイテムに置き換わり、オーグメントは既定のオーグメントになり、カスタム説明は空になる。装備しているアイテムと同じアイテムの行を押すと、装備・オーグメント・カスタム説明はどれも変わらない。どちらの場合もモーダルは閉じない。
- **AC36**（手順4）: 一覧では、そのスロットに装備しているアイテムの行が選択中の表示になる。
- **AC37**（手順4）: モーダルの上段には、装備しているアイテムの名前とアイテム説明文の全文が出る。装備が無いときは「装備が選択されていません。下の一覧から選択してください。」と出る。
- **AC38**（手順6）: 「装備を外す」を押すと、そのスロットは装備無しになる。モーダルは開いたままで、上段は装備の無いスロットの表示（AC37 の文言。AC73 のとおりオーグメントの選択肢・カスタム説明の欄・「装備を外す」は出ない）になる。
- **AC72**（手順5）: 装備選択モーダルは、題の横の閉じるボタンを押すか Esc キーを押すと閉じる。画面の幅が 768px を超えるときは、モーダルの外側を押しても閉じる。モーダルで行った装備・オーグメント・カスタム説明の変更は、モーダルを閉じても取り消されず、閉じた後の装備グリッドに出る。

### J4: オーグメントとカスタム説明を設定する

- **AC39**（手順2）: オーグメントの選択肢は、未選択を表す「-- オーグメント --」と、そのアイテムのオーグメントのデータにある経路とランクのすべての組を「<経路名> Rank <ランク>」の形で並べたものである。1 つの選択欄で経路とランクの組を選ぶ。
- **AC40**（手順2）: オーグメントのデータが無いアイテムでは、オーグメントの選択肢を選べない。
- **AC41**（手順2）: オーグメントを選ぶと、そのオーグメント文が選択肢の横に表示される。「-- オーグメント --」に戻すとオーグメント文は消える。
- **AC42**（手順3）: カスタム説明は 1 行のテキストとして入力できる。
- **AC43**（手順3）: カスタム説明の欄の「?」を押すと、カスタム説明の書き方の説明が装備選択モーダルの上に重なって開く。書き方の説明には「語の後にコロンを書くと、そこから行の末尾までは装備者本人の効果として数えない」という一文がある。「本人」は利用者向けの言い方で、0004 の「装備者本体」と同じ意味である（コロンの付いた語の扱いの規則は → 0004 の条件ラベルとラベルの適用範囲）。
- **AC44**（手順4）: オーグメントを選んだ装備のスロットには「Aug」の印が、カスタム説明が空でない装備のスロットには「メモ」の印が装備グリッドに出る。
- **AC73**（手順1）: 装備のあるスロットの装備選択モーダルを開くと、上段のオーグメントの選択肢はそのスロットで選んでいるオーグメント（選んでいなければ「-- オーグメント --」）を示し、カスタム説明の欄はそのスロットのカスタム説明を示す。装備の無いスロットのモーダルには、オーグメントの選択肢・カスタム説明の欄・「装備を外す」が出ない。

### J5: 装備セットを複製・削除・並べ替えする

- **AC45**（手順1）: 「複製」を押すと、同じキャラクターとジョブに、新しい装備セットの ID を持ち、16 スロットの装備とステータスビューの選択が複製元と同じで、名前が「<元の名前> のコピー」の装備セットが保存される。複製元の内容（元の名前・16 スロットの装備・ステータスビューの選択）は、複製を保存する直前に保存先から読み直したものを使い、画面に表示している内容は使わない（0001 AC60）。複製元が保存先から消えていたときは複製せず、AC69 の失敗として扱う。その名前が既にあるときは「<元の名前> のコピー 2」「<元の名前> のコピー 3」… のうち使われていない最小の番号の名前になる。名前が既にあるか・どの番号が使われているかは、複製を保存する直前に保存先から読み直した、同じキャラクターとジョブの装備セットの一覧で決める。
- **AC46**（手順1）: 複製した装備セットはタブの末尾に加わり、選択中のタブになる。
- **AC47**（手順2）: 「削除」は保存済みの装備セットを開いているときだけ表示される。押すと「装備セット「<名前>」を削除しますか？」と確認し（<名前> は名前の入力欄の値ではなく、最後に読み込んだか保存した装備セットの名前）、了承したときだけ削除する。
- **AC48**（手順2）: 削除した後は、同じキャラクターとジョブの残りの装備セットのうち並び順で先頭のものが読み込まれる。残りが無いときは装備セットの編集フォームが表示されない。
- **AC49**（手順3）: タブ A をタブ B の上に落とすと、A は B があった位置へ移り、A と B の間にあったタブは 1 つずつずれる。並び順は保存され、再読み込みしても保たれる。
- **AC50**（手順3）: 並べ替えても、装備セットの編集フォームに読み込んでいる装備セットと選択中のタブは変わらず、装備セットの編集フォームの内容と未保存の変更もそのまま残る。
- **AC51**（手順3）: 並べ替えは、同じキャラクターとジョブの中の並び順だけを変える。
- **AC65**（手順2）: 削除は、削除する装備セット 1 つ（装備セットの ID で同じものとみなす）を競合の単位として、0001 の AC43・AC44 に従う。保存先から消すとき（競合が無いとき、または競合の警告で「上書きして保存」を選んだとき）は、その装備セット 1 つだけを削除し、他の装備セットは読み直した内容のまま残す。削除しようとした装備セットが既に保存先から消えていたとき（0001 AC44）は、削除に成功したときと同じくタブからその装備セットを除いて AC48 のとおり読み込み、既に消えていたことは知らせない。
- **AC70**（手順2）: 削除で出た競合の警告（AC65）で「相手の変更を読み込む」を選ぶと、装備セットは削除されず、装備セットの編集フォームにその装備セットの別の画面で保存された内容が読み込まれる。装備セットの編集フォームに未保存の変更があっても、未保存の確認ダイアログを出さずにその変更を捨てる（削除の確認（AC47）を承諾した時点で、編集を捨てる意思があるとみなす。AC64）。
- **AC66**（手順3）: 並べ替えは、同じキャラクターとジョブの装備セットの一覧を並べ替えの対象の一覧（0001 の「並び替えの対象の一覧」）として、0001 の AC45 に従う（競合の警告は出さない）。装備セットの中身（名前・16 スロットの装備・ステータスビューの選択）は並べ替えでは変わらない。
- **AC67**（手順1）: 複製は、0001 の AC46・AC60 に従い、新しい装備セット 1 つを加えるだけで、競合の警告を出さない。複製の元の装備セットと他の装備セットは、複製によって変わらない。
- **AC69**（手順1〜3）: 複製・削除・並べ替えの保存に失敗したときは、0001 AC52 の共通の規則に従い、失敗を通知し、同じキャラクターとジョブの装備セットのタブの並びを操作の前の表示に戻す。選択中のタブと装備セットの編集フォームの内容（未保存の変更を含む）も操作の前に戻し、AC46・AC48 の読み込みは行わない。複製・削除・並べ替えでは未保存の確認ダイアログが出ない（AC55・AC64・AC59）ので、「操作の前」は、その操作のボタンを押した（タブを落とした）時点の表示である。

### J6: 未保存の変更を扱う

- **AC52**（手順1）: 装備セットの編集フォームの未保存の変更は、名前・ステータスビューの選択・16 スロットの装備（アイテム・オーグメントの選択・カスタム説明）を、最後に読み込んだか保存した装備セットの内容と比べて決める。名前は前後の空白を除いて比べる（前後の空白を足したり除いたりしただけでは未保存の変更にならない）。0008 の AC19・AC20 でステータスビューの選択の表示を既定に置き換えたことは、比べる対象にならない（→ 0008 AC40）。
- **AC53**（手順1）: 未保存の変更がある間は、名前の入力欄の横に「未保存」、選択中のタブに「●」が表示される。未保存の変更が無いときはどちらも表示されない。
- **AC54**（手順1）: 「保存」は未保存の変更があるときだけ押せる。押せない間は、ポインタを重ねると「変更がありません」と出る。
- **AC55**（手順1）: 「複製」と「共有」は、新規フォームを開いている間と、未保存の変更がある間は押せない。新規フォームを開いている間は、未保存の変更の有無によらず、ポインタを重ねると「装備セットが保存されていません。先に保存してください」と出る。新規フォームでない装備セットに未保存の変更がある間は、ポインタを重ねると「未保存の変更があります。先に保存してください」と出る。「共有」は、ログインしていない間も押せない（そのときの文言と、この AC の条件にも当たるときにどちらの文言を出すかは → 0009 AC5）。「共有」ボタンの位置と、押したときの振る舞いは 0009 が定める。
- **AC56**（手順1）: 編集した値を手で元の値に戻すと、未保存の変更は無い状態に戻る。
- **AC57**（手順1）: 装備しているアイテムと同じアイテムを一覧から選び直しても、未保存の変更にならない（AC35）。
- **AC58**（手順2）: 未保存の変更があるとき、次の 4 つの操作で未保存の確認ダイアログが出る。ダイアログに出る操作の名前（→ 0001）は、各操作の後ろの括弧内の文字列である。
  - 選択中でないタブを押す（装備セット「<押したタブの装備セットの名前>」へ切り替え）
  - 「+」を押す（新しい装備セットの作成）
  - キャラクターを変える（キャラクターの変更）
  - ジョブを変える（ジョブの変更）
- **AC59**（手順2）: 次の操作では、未保存の変更があっても未保存の確認ダイアログは出ず、編集内容も失われない: サイドバー・ブラウザの「戻る」「進む」・URL の直接入力で別の画面へ移って戻る、サポートジョブを変える、装備選択モーダルを開閉する、選択中のタブを押す、タブを並べ替える（AC50）。インポート（→ 0009）は共有閲覧モードで行い、そのときの装備セットの編集フォームには利用者の未保存の変更が無いので、インポートでも未保存の確認ダイアログは出ない。
- **AC60**（手順2）: 装備セットについての未保存の確認ダイアログは、変更が保存されていない対象を「装備セット「<名前の入力欄の値>」」として示す（名前の前後の空白の扱いと、名前が空のときの表示は → 0001）。ログアウトの確認で未保存の対象を挙げるときも、装備セットはこの呼び名で挙げる（→ 0001）。
- **AC61**（手順3）: 「保存して続行」は「保存」と同じ保存（AC19・AC23〜AC25）を行う。AC17・AC18 の場合は保存できない（保存できないときのダイアログの振る舞いは → 0001）。開いている装備セットが保存先から消えていたときは AC24 の選択肢を出し、「新しい装備セットとして保存」で保存できたときと「破棄」を選んだときは元の操作を続け、「キャンセル」を選んだときは元の操作を行わず未保存の確認ダイアログに戻る。
- **AC62**（手順3）: 「破棄して続行」を選ぶと、装備セットの編集フォームの名前・16 スロットの装備・ステータスビューの選択を、最後に読み込んだか保存した内容に戻してから操作を続ける。
- **AC63**（手順3）: キャラクターやジョブの変更で出た未保存の確認ダイアログで「キャンセル」を選ぶと、キャラクターとジョブの選択欄の表示が変更前の値に戻る。
- **AC64**（手順3）: 削除（AC47）では未保存の確認ダイアログは出ず、削除の確認だけが出る。
- **AC68**: 装備セット画面で選んでいたキャラクターをキャラクター画面で削除すると（→ 0002）、装備セット画面に戻ったとき、キャラクターの選択は未選択（「-- キャラクターを選択 --」）に戻り、ジョブとサポートジョブも未選択に戻り（AC7）、装備セットの編集フォームは閉じる。装備セットの編集フォームに未保存の変更があっても、未保存の確認ダイアログを出さずに捨てる（キャラクターの編集フォームで開いていたキャラクターを削除したときと同じ扱い → 0002）。この未保存の変更が失われることは、キャラクターの削除の確認の文言で知らせてある（→ 0002 AC53）。

- カスタム説明の書式、条件ラベル、装備テキスト群から値を拾う規則、「?」で開く書き方の説明の中身（AC43 で定める一文を除く）（→ 0004-equip-interpretation.md）
- 装備やサポートジョブを変えたときにステータスがいつ・どう計算し直されるか、サポートジョブがステータスの計算にどう使われるか（→ 0007-status-calculation.md）

- ステータスビューとユーザー定義プロパティの管理（→ 0003-status-view-management.md）

- 同じアイテムを左右の耳・指に同時に装備できるかの検査など、ゲーム内の装備制限の再現

## 制約

- オーグメントのデータはアイテムデータとは別のデータとしてリポジトリに置き、手元のスクリプトで更新してコミットする。ビルドのたびには更新しない。そのため、アイテムデータにあってオーグメントのデータに無いアイテムがありうる（出典: [ADR 0004](../adr/0004-augment-data-managed-separately.md)）
- オーグメントは経路とランクを選ぶ方式にする。オーグメントのデータが無いアイテムでは選択肢を選べなくし、カスタム説明で補えるようにする（出典: [ADR 0004](../adr/0004-augment-data-managed-separately.md)）
- 装備グリッドは表示専用にし、装備の検索・オーグメント・カスタム説明の編集は装備選択モーダルに集める。装備グリッドの並びは FF11 の装備画面に合わせ、スロットのデータの定義順とは独立にする（出典: [ADR 0014](../adr/0014-equipset-grid-modal.md)）
- 装備グリッドとステータス欄は左右 2 列に並べ、画面の幅が 1100px 以下では縦に積む。装備グリッドはスクロール中も画面に残す（出典: [ADR 0014](../adr/0014-equipset-grid-modal.md)）
- 一覧の行を押して装備を選んでも、装備選択モーダルは閉じない（出典: [ADR 0014](../adr/0014-equipset-grid-modal.md)）
- 装備選択モーダルの一覧は装備検索画面の結果の表を流用する（出典: [ADR 0014](../adr/0014-equipset-grid-modal.md)）
- 装備は識別子を持たず、アイテムを id で参照し、オーグメントは選んだ経路とランクだけを持つ（出典: [ADR 0018](../adr/0018-equip-module-owns-interpretation.md)）
- 装備セットは作った時点に端末側で振る不変の ID（装備セットの ID）で同じものとみなし、同一性・競合の単位・保存先での識別キーにする。キャラクター・ジョブ・名前の組は、重複を禁じる制約としてだけ残す（出典: この grill で決定: 名前で同一とみなすと、名前を変えた後に同じ装備セットだと判定する手がかりが無く、別の画面での名前の変更を保存の競合（AC23）や保存先から消えていた場合（AC24）と区別できないため。キャラクターの ID（→ 0002）と同じ理由 / 却下案: キャラクター・ジョブ・名前で同一とみなす（[ADR 0018](../adr/0018-equip-module-owns-interpretation.md) の `EquipSet` の同一性と、[ADR 0005](../adr/0005-localstorage-default-supabase-optin.md) の識別キー `(user_id, name, character_name, job)`。ADR 0018・ADR 0005 を改訂する））
- 保存の直前に、開いている装備セットが保存先から消えていたら、知らせて「新しい装備セットとして保存」「破棄」「キャンセル」から選ばせ、新しい装備セットとして保存するときは新しい装備セットの ID を振る（出典: この grill で決定: 別の画面での削除を黙って取り消さず、利用者が気づけるようにするため。キャラクター（→ 0002 AC44）と規則を揃える。新しい ID にするのは、削除された装備セットとは別の装備セットとして扱うため / 却下案: 知らせずに新規の装備セットとして保存し直す（前の決定 0002-Q3））
- 装備セットはキャラクターを、キャラクターを作った時点に振る変わらない ID で指す（出典: この grill で決定: キャラクターの名前を変えても装備セットとの結び付きが切れないようにするため / 却下案: 装備セットがキャラクターを名前で指す（[ADR 0005](../adr/0005-localstorage-default-supabase-optin.md) の識別キー `(user_id, name, character_name, job)`。ADR 0005 を改訂する））
- 保存は開いている装備セット 1 つだけを差し替えて書き、その装備セットが読み込んだ時点から別の画面で変わっていたら競合の警告を出す（出典: この grill で決定: 2 つの画面で同時に編集したとき、他方の保存を黙って上書き・削除しないため / 却下案: 一覧全体を渡して差分を取る（[ADR 0005](../adr/0005-localstorage-default-supabase-optin.md)。ADR 0005 を改訂する））
- ステータスビューの選択は装備セットのレコードに載せ、保存したときだけ書き込む（出典: [ADR 0015](../adr/0015-property-sets.md)）
- 確認を出すのは実際に編集内容が失われる操作だけにする。装備セット画面から離れるサイドバーでの画面の切り替えは画面を破棄しないので確認しない。サポートジョブは装備セットに保存されないので確認しない。削除はブラウザ標準の確認に任せる（出典: [ADR 0020](../adr/0020-unsaved-changes-guard.md)）
- 並べ替えでは、読み込んでいる装備セットと選択中のタブを変えず、未保存の確認ダイアログを出さない（出典: この grill で決定: 並べ替えは装備セットの中身を変えず（AC51・AC66）、読み込み直さなければ編集内容は失われないので、上の「実際に編集内容が失われる操作だけ」に沿う / 却下案: 並べ替えた後に移動した装備セットを読み込み、未保存の変更があれば確認する（前の実装と前の AC50・AC58。[ADR 0020](../adr/0020-unsaved-changes-guard.md) のガード対象から並べ替えを外す改訂をする））
- レベルが 0 になったジョブの装備セットは削除せずに残す（出典: この grill で決定: レベル 0 のジョブはステータスが求まらない（→ 0007）ので開けても使えないが、データを消さなければレベルを戻したときに失われないため / 却下案: レベル 0 のジョブの装備セットも開けるよう、ジョブの選択肢に加える）
- 「保存」は未保存の変更が無ければ押せなくし、「複製」「共有」は保存済みの内容に対する操作なので未保存の変更がある間は押せなくする（出典: [ADR 0020](../adr/0020-unsaved-changes-guard.md)）
- 「複製」「共有」は新規フォームでも押せなくする（出典: この grill で決定: ADR 0020 の「保存済みの内容に対する操作」という位置づけでは、新規フォームには対象が無いため / 却下案: 押せて、押した後に通知で止める（今の実装））
- 「破棄して続行」は、最後に読み込んだか保存した時点の装備セットの内容の控え（写し）に、装備セットの編集フォームを戻す（出典: [ADR 0020](../adr/0020-unsaved-changes-guard.md)）
- スロットの定義は Rust と Web で共有するテーブルデータ（`data/equipment_slots.json`）に置く（出典: [ADR 0002](../adr/0002-shared-table-data-json.md)）

## 設計上の論点

- **D2**: 既存データを装備セットの ID へどう移すか。ID の無い装備セットの記録（端末内データ・アカウントデータの両方）に、いつ・どこで ID を振るか。キャラクターの ID への移行（→ 0002 D1）と一緒に設計し、決めた内容は ADR に記録する。
- **D3**: 保存先から消えていたことを知らせる表示（AC24）の形と文言。キャラクターの同じ表示（→ 0002 D12）と揃えて決める。
- **D4**: 別の画面でキャラクターごと削除されていたとき（キャラクターの削除で装備セットも消える → 0002 AC61）、AC24 の「新しい装備セットとして保存」を選べると、存在しないキャラクターに属する装備セットができる。このときの選択肢と、装備セット画面のキャラクターの選択欄の扱いをどうするか。
