# キャラクターの管理

この仕様書の用語は [用語集](../../../CONTEXT.md) と、依存する仕様書（[0001 保存と同期](0001-saving-and-sync.md)）の用語節に従う。この仕様書で定義する語は「用語」節に書く。

## 用語

**キャラクター**:
ユーザーが登録して保存する 1 人分の育成状態。名前・種族・全ジョブのレベルとマスターレベル・メリットポイント・ジョブポイント・スキル値を持ち、キャラクターの ID で同じものとみなす。
_使わない_: プロファイル、キャラクタープロファイル

名前は利用者が後から変えられる。名前は端末内データ（→ 0001）の中、アカウントデータ（→ 0001）の中でそれぞれ重複しない（前後の空白を除いて比べる）。
メリットポイントは、基本ステータス 9 項目に対応する 9 項目（UI 上の区分名は「基礎ステータス」）・スキル 33 項目・その他 5 項目と、ジョブごとのジョブ別メリットポイント（グループ 1・グループ 2）からなる。
ジョブポイントはジョブごとの 10 カテゴリのランクである。スキル値は 33 項目の数値で、スキル値の入力上限ではない。
キャラクター一覧の並び順は、個々のキャラクターの中身ではなく、キャラクター一覧が持つ。

**キャラクターの ID**:
新規のキャラクターの編集フォームを開いた時点で端末側で振られ（AC38）、その後変わらない識別子。保存に失敗して保存し直しても、同じ ID を使う。ID は UUID で、端末内データとアカウントデータのどちらにあるかによらず、すべての保存先を通じて一意である。キャラクターが同じものかどうかは ID だけで決まり、名前を変えても同じキャラクターのままである。
装備セット（→ 0006）など、キャラクターに結び付く他のデータはキャラクターを ID で指す。ID は利用者が入力・編集するものではない。

**キャラクター画面**:
サイドバーから開く、キャラクター一覧とキャラクターの編集フォームからなる画面。URL のハッシュは `#/characters`。

**キャラクター一覧**:
キャラクター画面のうち、保存されたキャラクターを 1 行に 1 人ずつ、並び順のとおりに並べる領域。並び順は個々のキャラクターの中身ではなく、キャラクター一覧が持つ（[ADR 0022](../adr/0022-character-list-order.md)）。

**キャラクターの編集フォーム**:
キャラクター 1 人分の内容を入力する、キャラクター画面の領域。新規作成と既存キャラクターの編集で同じものを使う。
開いているキャラクターの編集フォームは同時に 1 つだけである。
_使わない_: 編集フォーム（修飾なしで使わない）

**スキル値の入力上限**:
スキル値の欄ごとに入力できる最大値。ジョブレベルが 1 以上の各ジョブについて、そのジョブの今のジョブレベルとマスターレベルでのそのスキルの上限を求めた、その最大値。
種族とメリットポイントは使わない（スキルのメリットポイントはスキル上限を広げず、ステータスの計算で有効スキル値に足す → 0007）。どのジョブもそのスキルを持たない場合は 0 である。
今のジョブでの上限（スキル上限 → 0007）とは別の語である。
根拠は [docs/internal/knowledge/status/skill_cap.md](../knowledge/status/skill_cap.md)。

**スキル値の追従**:
スキル値の入力上限が変わったとき、変わる前のスキル値の入力上限と同じ値だったスキル値だけを新しいスキル値の入力上限に置き換えること。
スキル値の入力上限が下がったときは、さらに、新しいスキル値の入力上限を超えるスキル値を新しいスキル値の入力上限に丸める。
利用者が上限と異なる値を入れたスキル値は、新しいスキル値の入力上限を超えない限り変えない。

**記録の補完**:
保存されたキャラクターを読み込んだときに、AC23 の項目（ジョブレベル・マスターレベル・メリットポイント・ジョブポイント・スキル値）の記録が欠けていれば埋め、埋めた内容を保存し直すこと。
埋める値の規則は受け入れ基準 AC31 に書く。ステータスの計算（→ 0007）は補完した後の保存された値を使い、計算の時点では補わない。

**対象ジョブ**:
キャラクターの編集フォームの「ジョブ別ポイント」セクションで、ジョブ別メリットポイントとジョブポイントのどちらを表示・入力するかを決める 1 つのジョブ。

**グループ合計上限**:
複数の項目の合計に掛かる上限。メリットポイントの「その他」5 項目と、ジョブ別メリットポイントの各グループに掛かる。
ある項目に入れられる最大値は、項目ごとの上限と「グループ合計上限から他の項目の合計を引いた残り」の小さい方になる。

## 課題

- **P1**: 利用者は、ステータスを計算するたびに種族・全ジョブのレベル・メリットポイント・ジョブポイント・スキル値を入れ直したくない。
- **P2**: 利用者は、ゲーム上あり得ない値（上限を超えるメリットポイントやスキル値）を誤って入れると、計算結果が実際と食い違っても気づけない。
- **P3**: 入力項目が 140 を超えるため、利用者は 1 箇所だけ直したいときに目的の欄を探すのに手間がかかる。
- **P4**: 利用者は、編集した内容を保存し忘れたまま別の操作（別の画面への移動を含む）をして、編集を失いたくない。
- **P5**: 複数のキャラクターを登録する利用者は、一覧を自分の使いやすい順に並べておきたい。
- **P6**: 利用者は、キャラクターの名前を直したときに、そのキャラクターの装備セット（→ 0006）を失いたくない。

## ユーザーストーリー

- **S1**: 利用者として、新しいキャラクターを名前・種族・育成状態と一緒に登録したい（→ P1）
- **S2**: 利用者として、登録済みのキャラクターの育成状態を後から直したい（→ P1, P3）
- **S3**: 利用者として、ゲーム上の上限を超える値を入力できないようにしてほしい（→ P2）
- **S4**: 利用者として、保存していない編集がある状態で編集が失われる操作をしたら、保存するか捨てるかを選びたい（→ P4）
- **S5**: 利用者として、使わなくなったキャラクターを、そのキャラクターの装備セットと一緒に削除したい（→ P1）
- **S6**: 利用者として、キャラクター一覧の並び順を自分で決め、その順番を保ちたい（→ P5）
- **S7**: 利用者として、キャラクターの名前を変えても、そのキャラクターの装備セットをそのまま使い続けたい（→ P6）
- **S8**: 利用者として、以前の版で保存したキャラクターを入れ直さずに使い続けたい（→ P1）

## ユーザージャーニー

### 全体の流れ

キャラクター画面は、キャラクター一覧とキャラクターの編集フォームからなる。キャラクターの編集フォームは一覧の「新規キャラクター」（J1）か、
一覧の行の「編集」（J2）で開く。保存するとキャラクターの編集フォームは閉じる。キャラクターの編集フォームに未保存の変更（→ 0001）があるまま、
編集が失われる操作や別の画面への移動（サイドバー・ブラウザの「戻る」「進む」・URL の直接入力）をすると、未保存の確認ダイアログ（→ 0001）を挟む（J3）。
削除（J4）と並び替え（J5）は一覧の行から行う。並び替えはキャラクターの編集フォームの状態と独立している（AC60）。削除はキャラクターの編集フォームの状態に影響しうる（AC55・AC64・AC65）。

### J1: 新しいキャラクターを登録する（→ S1, S3）

1. 利用者が一覧の「新規キャラクター」を押す。
2. 既定値の入ったキャラクターの編集フォームが開く。
3. 利用者が名前を入れ、種族を選ぶ。
4. 利用者が必要なセクションを開き、ジョブレベル・メリットポイント・ジョブポイント・スキル値を入れる。
5. 利用者が「保存」を押す。
6. キャラクターが一覧の末尾に加わり、キャラクターの編集フォームが閉じる。

### J2: 登録済みのキャラクターを編集する（→ S2, S3, S7）

1. 利用者が一覧の行の「編集」を押す。
2. 保存済みの内容が入ったキャラクターの編集フォームが開く。
3. 利用者が目的のセクションを開き、値（名前を含む）を直す。
4. 利用者が「保存」を押す。
5. 一覧の同じ位置のキャラクターが更新され、キャラクターの編集フォームが閉じる。

### J3: 未保存の変更があるまま、編集が失われる操作をする（→ S4）

1. キャラクターの編集フォームに未保存の変更がある状態で、利用者が編集の失われる操作か、別の画面への移動をする。
2. 未保存の確認ダイアログが出る。
3. 利用者が選択肢のどれかを選ぶ。

### J4: キャラクターを削除する（→ S5）

1. 利用者が一覧の行の「削除」を押す。
2. ブラウザ標準の確認が出る。そのキャラクターに装備セットがあれば、一緒に削除される件数も示される。そのキャラクターの装備セットに未保存の変更があれば、それが失われることも示される。
3. 利用者が承諾すると、キャラクターとその装備セットが削除され、キャラクターが一覧から消える。

### J5: キャラクター一覧を並び替える（→ S6）

1. 利用者が一覧の行のドラッグハンドル（⠿）を掴む。
2. 利用者が別の行の上に落とす。
3. 掴んだキャラクターが落とした行の位置へ移り、その並び順が保存される。

## 受け入れ基準

### 全体

- **AC1**: キャラクター一覧の各行には、キャラクターの名前と種族の日本語名が表示される。
- **AC2**: キャラクターが 1 人も登録されていないとき、一覧には「キャラクターが登録されていません」と表示される。
- **AC3**: ログインしていない間は端末内データの中で、ログインしている間はアカウントデータの中で、前後の空白を除いた名前が等しいキャラクターは 2 人以上存在しない。新規作成でも既存のキャラクターの編集でも、保存の直前に保存先から読み直した全キャラクターのうち、自分以外のキャラクターに同じ名前があれば保存できない（AC36・AC43）。2 つの画面がほぼ同時に同じ名前で保存したときにこの条件をどう保証するかは D9 で決める。
- **AC4**（J1 手順4・J2 手順3）: キャラクターの編集フォームは「基本情報」「ジョブレベル」「メリットポイント (共通)」「ジョブ別ポイント」「スキル値」の 5 つの開閉できるセクションからなる。
- **AC5**: そのブラウザで初めてキャラクターの編集フォームを開いたとき、開いているセクションは「基本情報」と「ジョブレベル」だけである。
- **AC6**: 利用者がセクションを開閉すると、その開閉状態は同じブラウザで次にキャラクターの編集フォームを開いたときも保たれる。
- **AC7**: 各セクションの見出しには、畳んだ状態でも次の要約が表示される。
  基本情報は「名前 / 種族」（名前が空なら「(名称未設定)」）。
  メリットポイント (共通) は基礎・スキル・その他それぞれの「合計 / 合計の最大」。合計の最大は、基礎が 135（9 項目 × 15）、スキルが 264（33 項目 × 8）、その他が 10（グループ合計上限）である。
  ジョブ別ポイントは対象ジョブ名、グループ 1 とグループ 2 の合計（各 / 10）、ジョブポイントの消費量の合計（/ 2100）。
  スキル値は項目数（33）と、スキル値の入力上限が 0 の項目数（1 件以上あるときだけ）。
  ジョブレベルには要約を出さない。
- **AC8**: ジョブレベルとマスターレベルを除く数値の欄には「/ 最大値」が並んで表示され、値が最大値に達した欄（最大値が 0 の欄を除く）は最大値が強調表示される。最大値は項目ごとの上限（AC12 の表の「項目ごとの範囲」の上端）で、グループ合計上限のある欄でも AC13 の残りではない。
- **AC9**: 数値の欄にフォーカスすると、欄の中身が全選択される。
- **AC10**: キャラクターの編集フォームの上端に、タイトル（新規なら「新規キャラクター」、既存なら「キャラクター編集」）・未保存の変更の表示・「保存」・「閉じる」があり、フォームをスクロールしても画面上端に留まる。
- **AC11**: 未保存の変更があるときだけ、キャラクターの編集フォームに「未保存」の表示が出て、「保存」を押せる。未保存の変更が無いとき「保存」は押せない。
  未保存の変更の有無は、名前・種族・ジョブレベル・マスターレベル・メリットポイント・ジョブポイント・スキル値で判定し、対象ジョブの選択とセクションの開閉は判定に含めない。

#### 入力値の上限

- **AC12**（J1 手順4・J2 手順3）: 次の欄は、上限を超える値を入力するとその場で上限の値になる。負の値と数値でない値（空欄を除く。空欄は AC16）は 0 になる。小数は小数点以下を切り捨てた値になる。

  | 欄 | 項目数 | 項目ごとの範囲 | グループ合計上限 |
  |---|---|---|---|
  | ジョブレベル | 22 ジョブ（`data/jobs.json`） | 0〜99 | なし |
  | マスターレベル | 22 ジョブ | 0〜50 | なし |
  | メリットポイントのうち基本ステータス 9 項目に対応するもの（UI 上の区分名は「基礎ステータス」） | 9（HP・MP・STR・DEX・VIT・AGI・INT・MND・CHR） | 0〜15 | なし |
  | メリットポイント スキル | 33（`data/skills.json`） | 0〜8 | なし |
  | メリットポイント その他 | 5（敵対心+・敵対心-・クリティカルヒット率・被クリティカルヒット率・詠唱中断率） | 0〜5 | 合計 10 |
  | ジョブ別メリットポイント | 対象ジョブのグループ 1・グループ 2 の各項目（`data/job_merit_categories.json`） | 0〜5 | 各グループ 10 |
  | ジョブポイント | 対象ジョブの 10 カテゴリ（`data/job_categories.json`） | 0〜20 | なし |
  | スキル値 | 33（`data/skills.json`） | 0〜スキル値の入力上限 | なし |

- **AC13**: グループ合計上限のある欄では、入れられる値は「項目ごとの上限」と「グループ合計上限から同じグループの他の項目の合計を引いた残り」の小さい方までになる。残りが 0 未満のときは 0 までになる。
- **AC14**: スキル値の入力上限が 0 のスキル値の欄は入力できない。ジョブレベルを変えてスキル値の入力上限が 1 以上になると入力できるようになる。
- **AC15**: 保存済みのキャラクターに上限を超える値が入っていても、キャラクターの編集フォームを開いただけでは値は変わらず、未保存の変更も生じない。その欄を利用者が編集した時点で上限の値に丸められる。
- **AC16**: 数値の欄を空欄のまま保存すると、その欄は 0 として保存される。

#### スキル値の入力上限とスキル値

- **AC17**（J1 手順4・J2 手順3）: ジョブレベルかマスターレベルを変えると、スキル値の入力上限が計算し直され、スキル値の追従が行われる。スキル値の入力上限が下がったときは、新しいスキル値の入力上限を超えていたスキル値も新しいスキル値の入力上限の値になる。種族とスキルのメリットポイントを変えても、スキル値の入力上限とスキル値は変わらない。
- **AC18**（J1 手順4・J2 手順3）: 「全て上限値にする」ボタンは「スキル値」セクションの先頭にある。押すと、33 個のスキル値がすべてそれぞれのスキル値の入力上限の値になる。
- **AC72**（J2 手順3）: スキル値の入力上限にスキルのメリットポイントの分を足していたときに保存されたスキル値が、今のスキル値の入力上限を超えていても、読み込んだときと、キャラクターの編集フォームを開いたときには丸めない（AC15）。その欄を利用者が編集したときに今のスキル値の入力上限に丸め（AC15）、ジョブレベルかマスターレベルを変えてスキル値の入力上限が下がったときは AC17 のとおり丸める。例: 保存されたスキル値 440・今のスキル値の入力上限 424 の欄を開いただけでは 440 のまま残り、その欄を編集すると 424 を超える値は 424 になる。

#### ジョブ別ポイント

- **AC19**: 「ジョブ別ポイント」セクションの先頭に対象ジョブの選択が 1 つあり、ジョブ別メリットポイントとジョブポイントの両方の表示がそのジョブのものに切り替わる。
- **AC20**: 対象ジョブの選択は、キャラクターの編集フォームを閉じて別のキャラクターを開いても前の選択のまま保たれる。画面を再読み込みすると `data/jobs.json` の先頭のジョブ（戦士）に戻る。ログイン・ログアウトでは前の選択のまま保たれる。
- **AC21**: ジョブ別メリットポイントのうち、`data/job_merit_categories.json` で名前が「カテゴリN」（N は数字）の枠は表示しない。グループに表示する項目が 1 つも無いときは「(項目なし)」と表示する。表示しない枠の値も、グループの合計（AC7）、グループ合計上限の計算（AC13）、保存（AC23）、未保存の変更の判定（AC11）に含める。
- **AC22**: ジョブポイントの消費量の合計（AC7 の要約に出す値）は、各カテゴリのランク r について r × (r + 1) / 2 を足した値である。

#### 保存と同期

- **AC23**: 「保存」で保存されるのは、キャラクターの ID・名前・種族・全 22 ジョブのジョブレベルとマスターレベル・メリットポイント（基本ステータス 9 項目に対応する 9 項目・スキル 33 項目・その他 5 項目・全 22 ジョブのジョブ別メリットポイントのグループ 1 とグループ 2）・全 22 ジョブのジョブポイント（10 カテゴリのランク）・スキル値 33 項目である。
  あわせて、ジョブ別メリットポイントを持つ前の保存形式の欄 `merit_points.store_tp` に、侍のジョブ別メリットポイント グループ 1 の「ストアTP」と同じ値を書く。
- **AC24**: キャラクター（AC23 の内容）とキャラクター一覧の並び順は、ログインしていない間は端末内データに、ログインしている間はアカウントデータに保存される。ログインしている間に保存したキャラクターと並び順は、同期（→ 0001）によって、同じアカウントでログインした別の端末でも表示される。
- **AC25**: 対象ジョブの選択は保存されず、同期もされない。セクションの開閉状態（AC6）はこのブラウザだけに保存され、同期されない。
- **AC26**: 削除（J4）と並び替え（J5）は、操作した時点で保存される。「保存」を押す必要は無い。削除と並び替えで保存先へ書く規則は 0001 の J8（AC43〜AC45）に従い、キャラクターに固有の扱いは AC61〜AC65 に書く。
- **AC64**: 削除（J4）と並び替え（J5）の保存に失敗したときは、0001 AC52 の共通の規則に従い、失敗を通知し、キャラクター一覧を操作の前の表示に戻す。削除に失敗したときは、そのキャラクターはキャラクター一覧と装備セット画面のキャラクター選択の候補に残り、キャラクターの編集フォームで開かれていれば開いたまま、未保存の変更も残る（AC55・AC56 は当てはまらない）。
- **AC27**: 初回アップロード（→ 0001）が行われるとき、端末内データのキャラクターはすべて、キャラクターの ID・AC23 の内容・端末内データでの並び順を変えずにアカウントデータに加わる。
- **AC28**: キャラクターの競合の単位（→ 0001）はキャラクター 1 人（キャラクターの ID で同じものとみなす）で、保存の競合（→ 0001）はこの単位で判定する。保存するときは、そのキャラクター 1 人だけを差し替えて書き、他のキャラクターは変えない。
- **AC29**: キャラクターの保存（「保存」と、未保存の確認ダイアログの「保存して続行」）に失敗したとき、0001 の保存の失敗の振る舞い（失敗を通知し、編集内容をそのまま残す）に従い、キャラクターの編集フォームは開いたままで、未保存の変更も残る。
- **AC30**: ログインしている間にアカウントデータのキャラクターの読み込みに失敗したとき（→ 0001 AC4）、キャラクターの保存・削除・並び替えは行われず、アカウントデータは変わらない。装備セット（→ 0006）や、カスタムステータスビューとユーザー定義プロパティ（→ 0003）の読み込みだけに失敗したときは、キャラクターの保存と並び替えは止めない（キャラクターの削除は AC63）。
- **AC31**: 端末内データまたはアカウントデータからキャラクターを読み込んだとき、記録の補完が次の規則で行われる。
  ジョブポイントの記録が無いジョブ（そのジョブの 10 カテゴリのランクがそろっていないジョブを含む）は、10 カテゴリともランク 20 で埋める。10 カテゴリそろっていない記録は、記録済みのランクも残さない。
  ジョブポイントの記録はカテゴリの名前を持たない 10 個の並びなので、並びの長さが 10 でないとどのカテゴリが欠けたか分からない。このアプリは常に 10 個そろえて書くので、そろっていない記録は壊れたデータとみなす。
  スキルのメリットポイントの記録が無い項目は 8 で、ジョブ別メリットポイントの記録が無い項目は 0 で、それ以外のメリットポイント・ジョブレベル・マスターレベルの記録が無い項目は 0 で埋める。
  スキル値の記録が無いキャラクターは、33 項目をそれぞれのスキル値の入力上限の値で埋める。
  スキル値の記録があり一部の項目だけが無いキャラクターは、無い項目を 0 で埋める。
  埋めたキャラクターは、読み込んだのと同じ保存先（端末内データまたはアカウントデータ）に保存し直される。記録が欠けていないキャラクターは変わらない。
  この基準と AC32 は S8 にかかる。
- **AC32**: 記録の補完によって、キャラクターの編集フォームに未保存の変更は生じない。記録の補完の後に開いたキャラクターの編集フォームには、埋めた値が保存済みの値として入る。

### J1: 新しいキャラクターを登録する

- **AC33**（手順2）: 新規のキャラクターの編集フォームは次の既定値で開く。名前は空、種族はヒューム、全ジョブのジョブレベル 99・マスターレベル 0、
  メリットポイントのうち基本ステータス 9 項目に対応するものは各 15、スキル 33 項目は各 8、その他 5 項目は各 0、
  全ジョブのジョブ別メリットポイントは全項目 0、全ジョブのジョブポイントは 10 カテゴリとも 20、
  スキル値は 33 項目ともそれぞれのスキル値の入力上限の値。
- **AC34**（手順2）: 開いた直後の新規のキャラクターの編集フォームには未保存の変更が無い。
- **AC35**（手順5）: 名前が空（前後の空白を除いて空）のまま「保存」を押すと、「キャラクター名を入力してください。」と表示され、保存されず、キャラクターの編集フォームは開いたままになる。
- **AC36**（手順5）: 保存の直前に保存先から読み直した全キャラクターに、前後の空白を除いて同じ名前のキャラクターがあるときに「保存」を押すと、「キャラクター「<名前>」は既に存在します。」と表示され（<名前> は前後の空白を除いた入力値）、保存されず、キャラクターの編集フォームは開いたままになる。
- **AC37**（手順5）: 名前は前後の空白を除いて保存される。
- **AC38**（手順2・手順6）: 新規のキャラクターの編集フォームを開いた時点で、すべての保存先を通じて他のどのキャラクターとも異なるキャラクターの ID が振られ、保存したキャラクターはその ID を持つ。保存に失敗して保存し直したときも、同じ ID で保存される。
- **AC39**（手順6）: 保存したキャラクターは、保存の直前に保存先から読み直した一覧の末尾に置かれて表示され、装備セット画面（→ 0006）のキャラクター選択の候補にも加わる。
- **AC66**（手順1）: 「新規キャラクター」ボタンはキャラクター一覧の下にあり、キャラクターが 1 人も登録されていないときも表示される。未保存の変更が無いときに押すと、新規のキャラクターの編集フォーム（AC33）が開く。別のキャラクターの編集フォームが開いていたときは、そのキャラクターの編集フォームに代わって開く。未保存の変更があるときは AC47 の未保存の確認ダイアログが出る。
- **AC67**（手順3）: 種族の選択肢は「ヒューム」「エルヴァーン」「タルタル」「ミスラ」「ガルカ」の 5 つで、この順に並ぶ。

### J2: 登録済みのキャラクターを編集する

- **AC40**（手順2）: キャラクターの編集フォームには保存済みの値が入る。保存済みのデータに無かった項目は、記録の補完（AC31）で埋めて保存し直した値が入る。
  補った値は読み込んだ時点の内容として扱い、補ったことで未保存の変更は生じない。
- **AC41**（手順2）: 保存済みのメリットポイントに、ジョブ別メリットポイントとは別の欄（ジョブ別メリットポイントを持つ前の保存形式の欄 `merit_points.store_tp`）にストアTP の値があり、侍のジョブ別メリットポイント グループ 1 の「ストアTP」の項目が 0 のとき、その項目にストアTP の値が入る。この値は読み込んだ時点の内容として扱い、入ったことで未保存の変更は生じない。
- **AC42**（手順4）: 保存の直前に読み直したとき、編集しているキャラクターが、キャラクターの編集フォームに読み込んだ時点から別の画面で変わっていたら、競合の警告（→ 0001）が出る。どの選択肢を選んだときの振る舞いも 0001 に従う。
- **AC43**（手順4）: 保存の直前に保存先から読み直した全キャラクターのうち、自分以外のキャラクターと同じ名前（前後の空白を除いて比べる）で「保存」を押すと、AC36 と同じ文言が表示され、保存されず、キャラクターの編集フォームは開いたままになる。自分自身の今の名前のまま保存するときは、この表示は出ない。
- **AC44**（手順4）: 保存の直前に読み直したとき、編集しているキャラクターが保存先から消えていたら、保存せずに、そのキャラクターが保存先から消えていることを知らせ、「新しいキャラクターとして保存」「破棄」「キャンセル」から選ばせる。
  - 「新しいキャラクターとして保存」: 新しいキャラクターの ID を振り、編集の内容をそのキャラクターとして、保存の直前に読み直した一覧の末尾に保存する。キャラクターの編集フォームは閉じる。AC35・AC36・AC43 の条件はこの保存にも当てはまる。
  - 「破棄」: 何も保存せず、キャラクターの編集フォームを閉じ、編集の内容を捨てる。消えていたキャラクターは一覧から除かれる。
  - 「キャンセル」: 何も保存せず、キャラクターの編集フォームは開いたままで、未保存の変更も残る。
- **AC45**（手順5）: 保存した後も、そのキャラクターの一覧上の位置とキャラクターの ID は変わらない（AC44 の場合を除く）。
- **AC46**（手順5）: 名前を変えて保存しても、そのキャラクターの装備セットはすべて、装備セット画面でそのキャラクターを選んだときにそのまま表示される。
- **AC68**（手順1）: 未保存の変更が無いときに一覧の行の「編集」を押すと、その行のキャラクターのキャラクターの編集フォームが開く（内容は AC40・AC41）。別のキャラクターまたは新規のキャラクターの編集フォームが開いていたときは、そのキャラクターの編集フォームに代わって開く。未保存の変更があるときは AC47 の未保存の確認ダイアログが出る。

### J3: 未保存の変更があるまま、編集が失われる操作をする

- **AC47**（手順1）: キャラクターの編集フォームに未保存の変更があるとき、次の操作で未保存の確認ダイアログが出る。ダイアログに出る操作の名前は次のとおりである。

  | 操作 | 操作の名前 |
  |---|---|
  | 一覧の行の「編集」（開いているキャラクター自身を含む） | キャラクター「<その行のキャラクターの名前>」の編集 |
  | 一覧の「新規キャラクター」 | 新規キャラクターの作成 |
  | キャラクターの編集フォームの「閉じる」 | 編集フォームを閉じる |
  | キャラクター画面から、サイドバー・ブラウザの「戻る」「進む」・URL の直接入力のどれかで別の画面へ移る操作 | メニュー「<移動先の画面のサイドバー上の名前>」へ移動（例: メニュー「装備検索」へ移動） |

  別の画面へ移る操作は、URL のハッシュだけが変わり、移動先がキャラクター画面以外のサイドバーの画面になるものに限る。どの画面にも当たらないハッシュはキャラクター画面のまま表示されるので、別の画面へ移る操作ではない。ページの読み込みになる入力（ハッシュ以外を変える URL の直接入力）は 0001 の J6 に従う。
  開いているキャラクター自身の一覧の行の「編集」は、保存済みの内容でキャラクターの編集フォームを開き直す操作で、編集が失われるので確認の対象にする。

- **AC48**（手順1）: 次の操作では未保存の確認ダイアログを出さず、キャラクターの編集フォームの内容も変わらない。一覧の並び替え、対象ジョブの切り替え、セクションの開閉。
- **AC49**（手順2）: キャラクターについての未保存の確認ダイアログは、対象を キャラクター「<名前の入力欄の値>」 として示す（名前が空のときの表示は 0001 に従う）。
- **AC50**（手順3）: 「保存して続行」を選んだときの保存は、キャラクターの編集フォームの「保存」と同じ内容を保存し、AC35・AC36・AC43 と同じ条件で保存できない。保存できないときは、ダイアログに AC35・AC36 と同じ文言を表示し、ダイアログは開いたままになる。編集しているキャラクターが保存先から消えていたときは AC44 の選択肢を出し、「新しいキャラクターとして保存」で保存できたときと「破棄」を選んだときは元の操作を続け、「キャンセル」を選んだときは元の操作を行わず未保存の確認ダイアログに戻る。
- **AC51**（手順3）: 「破棄して続行」を選ぶと、キャラクターの編集フォームが閉じてから操作が行われる。
- **AC52**（手順3）: ブラウザの「戻る」「進む」・URL の直接入力で出た未保存の確認ダイアログで「キャンセル」を選ぶと、キャラクター画面が表示されたまま、URL のハッシュは `#/characters` に戻る。

### J4: キャラクターを削除する

- **AC69**（手順1）: 一覧の行の「削除」を押すと、キャラクターの編集フォームに未保存の変更があっても未保存の確認ダイアログは出ず、AC53 の確認が出る（AC65 の場合を除く）。
- **AC53**（手順2）: 確認の文言は「キャラクター「<名前>」を削除しますか？」である。そのキャラクターに属する装備セット（全ジョブの合計）が N 件（N ≥ 1）あるときは、続けて改行し「装備セット N 件も削除します。」を表示する。N が 0 のときはこの行を出さない。そのキャラクターに属する装備セットのうち、装備セットの編集フォーム（→ 0006）に未保存の変更があるものがあれば、続けて改行し「装備セット「<その装備セットの名前の入力欄の値>」の未保存の変更も失われます。」を表示する。名前は装備セットの編集フォームの名前の入力欄の値で、前後の空白を除いて表示し、空のときは「(名称未設定)」と表示する（→ 0001 AC30。0006 AC60 の呼び名と同じ）。拒否すると何も変わらない。
- **AC54**（手順3）: 承諾すると、キャラクターと、そのキャラクターに属する装備セットがすべて保存先から削除される。
- **AC55**（手順3）: 削除したキャラクターがキャラクターの編集フォームで開かれていた場合、キャラクターの編集フォームは閉じる。未保存の変更があっても未保存の確認ダイアログは出ない。
- **AC56**（手順3）: 削除したキャラクターは装備セット画面のキャラクター選択の候補からも消える。同じ名前のキャラクターを後から作り直しても、削除した装備セットは戻らない。
- **AC61**（手順3）: 削除は、削除するキャラクター 1 人を競合の単位として、0001 の AC43・AC44 に従う。加えて、保存先から読み直したそのキャラクターに属する装備セットが、この画面に読み込んだ（またはこの画面で最後に保存した）時点と異なるとき（装備セットの内容の変更、別の画面での追加・削除、それによる件数の違い）も、削除の保存の競合として競合の警告を出す。保存先から消すとき（競合が無いとき、または競合の警告で「上書きして保存」を選んだとき）は、そのキャラクターと、読み直した時点でそのキャラクターに属する装備セットのすべて（AC54）を、0001 AC53 のとおり 1 回の書き込みで削除し、他のキャラクターは変えない。削除しようとしたキャラクターが既に保存先から消えていたとき（0001 AC44）は、削除に成功したときと同じく一覧からそのキャラクターを除き（AC55・AC56 も同じく当てはまる）、既に消えていたことは知らせない。
- **AC63**（手順3）: ログインしている間にアカウントデータの装備セット（→ 0006）の読み込みに失敗しているとき（→ 0001 AC4）は、キャラクターの読み込みに成功していても、キャラクターの削除は行われず、キャラクターと装備セットのアカウントデータは変わらない。キャラクターの削除はそのキャラクターに属する装備セットの削除を伴うためである。
- **AC65**（手順3）: 削除で出た競合の警告（AC61）で「相手の変更を読み込む」を選ぶと、キャラクターは削除されず、キャラクターの編集フォームにそのキャラクターの別の画面で保存された内容が表示され、キャラクター一覧の行もその内容になる。そのキャラクターをキャラクターの編集フォームで開いていなかったときは、そのキャラクターを開く。装備セットだけが別の画面で変わっていたとき（AC61）も同じで、装備セットは削除されず、別の画面で保存された内容のまま残る。
  - そのキャラクター自身をキャラクターの編集フォームで開いていて未保存の変更があったときは、未保存の確認ダイアログを出さずにその変更を捨てる（削除の確認を承諾した時点で、そのキャラクターの編集を捨てる意思があるとみなす）。
  - 別のキャラクターまたは新規のキャラクターの編集フォームに未保存の変更があったときは、一覧の行の「編集」を押したときと同じく未保存の確認ダイアログ（AC47）を、操作の名前を「キャラクター「<削除しようとしたキャラクターの名前>」の編集」として出す。そこで「キャンセル」を選ぶと、キャラクターの編集フォームはそのままで、削除もされない。

### J5: キャラクター一覧を並び替える

- **AC57**（手順1）: ドラッグを始められるのはドラッグハンドルだけで、行のほかの部分（名前・「編集」・「削除」）を掴んでもドラッグは始まらない。
- **AC70**（手順2）: ドラッグしている間、掴んでいるキャラクターの行は半透明（不透明度 0.4）で表示され、ポインタが重なっている行は枠の色が変わる。
- **AC71**（手順2）: どの行の上でもない場所で離したときは、並び順は変わらず、保存も行われない。
- **AC58**（手順3）: 掴んだキャラクターは、落とした先の行の位置に入り、その間の行は 1 つずつずれる。自分自身の上に落としたときは何も変わらない。
- **AC59**（手順3）: ログインしていない間に並び替えた順番は端末内データに、ログインしている間に並び替えた順番はアカウントデータに保たれ、それぞれ画面を再読み込みした後も同じ順番で表示される。
- **AC60**（手順3）: 並び替えはキャラクターの編集フォームの内容と未保存の変更に影響しない。
- **AC62**（手順3）: 並び替えは、キャラクター一覧を並び替えの対象の一覧として、0001 の AC45 に従う（競合の警告は出さない）。キャラクターの中身（AC23 の内容）は並び替えでは変わらない。

- メリットポイントの総獲得量（ゲーム内の共有プール）。このツールは項目ごとの上限とグループ合計上限だけを扱う（[merit_points.md](../knowledge/status/merit_points.md)）

## 制約

- 未保存の確認ダイアログを出すのは、実際に編集が失われる操作と、キャラクター画面から別の画面へ移る操作（「キャラクター画面に未保存の変更があるとき」で始まる行）だけとする（出典: [ADR 0020](../adr/0020-unsaved-changes-guard.md)。別の画面へ移る操作を含める点は、その行の決定による）
- 削除は未保存の確認ダイアログではなくブラウザ標準の確認に任せる。削除するキャラクターの装備セットに未保存の変更があれば、そのことを確認の文言に足す（出典: この grill で決定: ADR 0020 の「削除はブラウザ標準の確認に任せる」を保ったまま、装備セットの未保存の変更が黙って消えるのを知らせるため / 却下案: 装備セットがあるキャラクターの削除は自前の確認にし、件数を示し、既定のボタンを「キャンセル」にする）
- キャラクターの編集フォームを閉じるボタンは「閉じる」とし、編集を捨てる操作として扱わない（出典: [ADR 0020](../adr/0020-unsaved-changes-guard.md)）
- キャラクター画面に未保存の変更があるとき、サイドバー・ブラウザの「戻る」「進む」・URL の直接入力で別の画面へ移る操作も未保存の確認ダイアログの対象にする。装備セット画面からの移動はこの対象にしない（出典: この grill で決定: 装備セット画面には必ず保存済みのキャラクターで入るため。この理由は移動の経路によらず成り立つ / 却下案: 画面の切り替えは確認しない（[ADR 0020](../adr/0020-unsaved-changes-guard.md)。キャラクター画面だけ確認する形に改訂した。実装は未対応））
- キャラクターは新規のキャラクターの編集フォームを開いた時点に端末側で振る不変の ID（UUID）で同じものとみなし、保存先での識別キーにする。装備セットなどキャラクターに結び付くデータは ID でキャラクターを指す。名前は識別キーにせず、重複しない制約だけを持つ（出典: この grill で決定: 名前を変えたときに装備セットとの結び付きが切れないようにするため / 却下案: キャラクターの識別キーは `(user_id, name)`、装備セットはキャラクター名で所属先を指す（[ADR 0005](../adr/0005-localstorage-default-supabase-optin.md)・[ADR 0006](../adr/0006-login-sync-conflict-resolution.md) を改訂する））
- 初回アップロードではキャラクターの ID を変えずにそのまま送る（出典: この grill で決定: 初回アップロードはアカウントで最初にログインしたときに 1 度だけ行い、その時点でアカウントは空なので、ID がアカウントデータの既存のキャラクターと重ならないため / 却下案: 名前が等しいキャラクターがアカウントデータにあれば、アカウントデータの側を優先して送らない（[ADR 0006](../adr/0006-login-sync-conflict-resolution.md) を改訂する））
- キャラクターを削除すると、そのキャラクターの装備セットも一緒に削除する（出典: この grill で決定: キャラクターを ID で指すようになると、削除したキャラクターの装備セットはどのキャラクターからも開けなくなるため / 却下案: 装備セットを残し、同じ名前のキャラクターを作り直すと再び見えるようにする）
- キャラクターの削除の保存の競合は、キャラクターに加えて、そのキャラクターに属する装備セットの変更・追加・削除についても判定し、異なれば競合の警告を出す（出典: この grill で決定: 別の画面で変わった・加わった装備セットを黙って消さないため。確認で示した件数と実際に消える件数のずれも同じ仕組みで防ぐ / 却下案: キャラクター 1 人だけで判定する。件数が確認の時点と違うときだけ確認を出し直す）
- 削除の競合の警告で「相手の変更を読み込む」を選んだとき、そのキャラクター自身の未保存の変更は確認なしに捨てる（出典: この grill で決定: 削除の確認を承諾するという明示の操作で、そのキャラクターの編集を捨てる意思を示しているため / 却下案: 未保存の変更があれば未保存の確認ダイアログを挟む。「相手の変更を読み込む」の説明文に編集中の内容が失われることを書く）
- 保存の直前に、編集しているキャラクターが保存先から消えていたら、知らせて「新しいキャラクターとして保存」「破棄」「キャンセル」から選ばせ、新しいキャラクターとして保存するときは新しい ID を振る（出典: この grill で決定: 削除では装備セットも一緒に消えるので、キャラクターだけが黙って復活すると利用者が装備セットの消失に気づけないため。削除の競合で警告を出すこととも扱いを揃える。新しい ID にするのは、削除されたキャラクターとは別のキャラクターとして扱うため / 却下案: 知らせずに新しいキャラクターとして保存し直す（前の決定 0002-Q3））
- AC23 の項目の記録が欠けたキャラクターは、読み込んだときに AC31 の値で埋めて保存し直し、ステータスの計算の時点では補わない（出典: この grill で決定: 計算とキャラクターの編集フォームが同じ保存された値を見るようにし、計算時に補う処理を無くすため。メリットポイントも含めるのは、計算とキャラクターの編集フォームが同じ保存された値を見るようにするため / 却下案: 計算のたびに最大の値で補う。読み込みではメモリ上で補うだけにし、利用者が次に保存したときに書く。保存形式に版番号を持たせ、1 度だけの移行にする。メリットポイントの欠けは表示だけで補い、保存し直さない（読み込みで書くことは [ADR 0021](../adr/0021-character-edit-density-and-sections.md) のドライバ「読み込んだだけで書き換えない」と食い違うので、ADR 0021 を改訂する））
- ジョブポイントの 10 カテゴリのランクがそろっていない記録は、記録済みのランクも残さず、10 カテゴリともランク 20 で埋める（出典: この grill で決定: 並びの長さが違うとどのカテゴリが欠けたか分からず、このアプリは常に 10 個書くので、そろっていない記録は壊れたデータとみなすため / 却下案: 欠けたカテゴリだけを 20 で埋め、記録済みのランクは残す（並びの先頭から対応するとみなす））
- キャラクターの編集フォームは開閉式の 5 セクションとし、対象ジョブの選択はジョブ別メリットポイントとジョブポイントで 1 つを共有する（出典: [ADR 0021](../adr/0021-character-edit-density-and-sections.md)）
- 上限を超える値は入力の時点で丸め、読み込みの時点では丸めない（出典: [ADR 0021](../adr/0021-character-edit-density-and-sections.md)）
- スキル値はスキル値の入力上限（→ 用語「スキル値の入力上限」）で丸め、メインジョブごとの丸めは計算側（→ 0007）が行う（出典: [ADR 0021](../adr/0021-character-edit-density-and-sections.md)）
- スキル値の入力上限には、スキルのメリットポイントの分を足さない（出典: この grill で決定: スキルのメリットポイントはスキル上限を広げず、ステータスの計算で有効スキル値に足すと 0007 で決めたため。入力上限に足すと、メリットポイントの分が計算で 2 度効く / 却下案: 各ジョブの上限の最大にスキルのメリットポイントのランク × 2 を足す（[ADR 0021](../adr/0021-character-edit-density-and-sections.md) の「既定のメリットを含めて算出する」を改訂する））
- ジョブ・種族・スキルの一覧と、ジョブ別メリットポイント・ジョブポイントのカテゴリ名は、Rust と Web で共通のテーブルデータから読む（出典: [ADR 0002](../adr/0002-shared-table-data-json.md)）
- キャラクターの並び順は配列の順序として保存し、表示順と保存順を一致させる。ログイン中は並び順をレコードの外（行の列）に持ち、キャラクターのデータの形に含めない（出典: [ADR 0022](../adr/0022-character-list-order.md)）
- 並び替えはドラッグハンドルだけで行い、落とした時点で保存する。並び替えは未保存の確認ダイアログの対象にしない（出典: [ADR 0022](../adr/0022-character-list-order.md)）
- 対象ジョブの選択は保存せず、画面を再読み込みすると `data/jobs.json` の先頭のジョブに戻す（出典: この grill で決定: 今の実装どおりとするため / 却下案: セクションの開閉状態と同じく、このブラウザに保存する）
- 未ログインでもキャラクターの登録・編集・削除・並び替えのすべてができる（出典: [ADR 0005](../adr/0005-localstorage-default-supabase-optin.md)）

## 設計上の論点

- **D1**: 既存データをキャラクターの ID へどう移すか。ID の無いキャラクターの記録（端末内データ・アカウントデータの両方）に、いつ・どこで ID を振るか。キャラクター名で所属先を指している装備セットを、ID で指す形へどう書き換えるか（同じ名前のキャラクターが端末内データとアカウントデータの両方にある場合を含む）。装備セットの ID への移行（→ 0006 D2）と一緒に設計する。決めた内容は ADR に記録する。
- **D2**: 記録の補完をいつ行うか（ページを開いたとき・ログインとログアウトの後・初回アップロードの後）と、補完した内容の保存が失敗したとき、または別の画面の保存と重なったとき（保存の競合）にどうするか。D1 の ID を振る移行も読み込みで書くので、D1 と同じ契機と失敗時の扱いにまとめて決める。
- **D5**: ブラウザの「戻る」「進む」で出た未保存の確認ダイアログで「キャンセル」を選んだとき（AC52）、ハッシュを戻すのにブラウザの履歴を積むか、置き換えるか。
- **D8**: 装備セットの読み込みに失敗しているときにキャラクターの削除を止めること（AC63）を、利用者にどう示すか（一覧の行の「削除」を押せなくするか、押したときに削除できない理由を出すか）。読み込みの失敗そのものの伝え方は 0001 の D1 で決める。
- **D9**: 名前の重複の禁止（AC3）を、2 つの画面がほぼ同時に同じ名前で保存したときにどう保証するか（例: アカウントデータでは前後の空白を除いた名前へのサーバー側の一意制約、端末内データではタブ間の排他）。保存の競合の判定と書き込みを不可分に行う手段（0001 AC58・D9）と揃えて決める。前後の空白だけが違う名前のキャラクターが既に保存先にあるときに、どう移行するか。
- **D10**: 数値の欄で、入力の途中で空欄を保つか、空欄にした時点で 0 にするかの欄ごとの扱い（AC16。GitHub issue #64）。
- **D11**: キャラクター 1 人だけを書く保存（AC28）で、新しいキャラクターを一覧の末尾に置く（AC39・AC44）ときの並び順の位置の振り方と、2 つの画面がほぼ同時に新しいキャラクターを作って位置が重なったときの順。決めた内容で [ADR 0022](../adr/0022-character-list-order.md) を改訂する。
- **D12**: 保存先から消えていたことを知らせる表示（AC44）の形と文言。
