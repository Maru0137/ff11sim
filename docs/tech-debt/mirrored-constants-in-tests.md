# テストが実装の定義をミラーしていて検証になっていない問題

`web/test/*.test.js` を Rust へ移植する過程 (docs/adr/0010 手順 5) で見つかった、
テスト設計上の問題。同じ構造が他にも残っていないか確認する際の手がかりとして残す。

## 何が起きていたか

`web/test/skillchain-bonus.test.js` は、ジョブ特性とジョブポイントギフトの定義を
**テストファイル自身の中に書き写して**いた。

```js
const SCB_TRAIT_CUMULATIVE = [8, 12, 16, 20, 23];
const SCB_TRAIT_LEVELS = { Sam: [78, 88, 98], ... };
const SCB_GIFT_TIERS   = { Sam: [[150,2],[450,2],[1125,2],[2000,2]], ... };

function skillchainBonusGift(job, totalJp) { /* SCB_GIFT_TIERS を読む */ }
```

そのうえで次のように検証していた。

```js
check('SAM 450 JP → +4', skillchainBonusGift('Sam', 450), 4);
```

自分で書いた定義を、自分で書いた関数で読み、期待値と比べている。**実装
(`rust/src/gift.rs`) を一切参照していない**ため、実装が何であってもこのテストは通る。

ファイル冒頭のコメントには「`data/job_gifts.json` の SkillchainBonus エントリを
ミラー」とあった。書いた時点では実装のコピーだったが、定義が `gift.rs` へ移行した際に
取り残された。ミラーは同期を人手に依存するため、こうなる。

## 実際に見逃されていた誤り

ギフトの 2 番目の閾値が食い違っていた。

| | 2 番目の閾値 |
|---|---|
| JS テストのミラー | 450 JP |
| 実装 (`gift.rs`) | **500 JP** |

`gift.rs` のギフト全系統が例外なく `150 / 500 / 1125 / 2000` のパターンを持つため、
実装側の 500 が正しい。450〜499 JP の範囲で結果が食い違うが、テストはミラーを
検証していたので検出できなかった。

## 影響範囲

同ファイルの 33 アサーションのうち、ソース 3 (ジョブ特性) とソース 4 (ギフト) が
これに該当する。ソース 1・2 (装備の説明文からの抽出) は実データを読むので有効だった。

## 対応

`rust/tests/skillchain_bonus.rs` へ移植する際に、`job.trait_bonus()` /
`job.gift_value()` という**実装そのもの**を呼ぶ形に変えた。閾値の食い違いが
見つかったのも実装を直接呼ぶようにしたためである。移植版では中間閾値
(499 / 500 / 1124 / 1125 / 1999 / 2000) を検証しており、同種の取り違えを検出できる。

## 事例 2: `AUGMENT_JA_TO_EN` の部分コピー

`web/test/ws-damage-sam-elemental.test.js` にも同じ構造があった。
オーグメントの日本語→英語 変換表を実装からコピーして持っている。

| | エントリ数 |
|---|---|
| 実装 (`web/js/constants.js`) | 76 |
| テストのミラー | **32** |

実装にしかないエントリが 44 件ある。状態異常レジスト系
(`レジストスリープ` / `テラー耐性` / `デス耐性` など) が丸ごと欠けている。
テスト独自のエントリは 0 件なので、**実装からの部分コピーが古いまま取り残された**もの。

事例 1 と違い「値が違う」のではなく「項目が足りない」パターン。このテストは
WS ダメージ% しか検証しないため、レジスト系が欠けていても期待値は変わらず、
問題が表面化していなかった。将来このテストにレジストの検証を足すと、実装では
変換できるのにテストでは変換できず、原因の分かりにくい失敗になる。

## 確認すべきこと

- 他のテストや実装で定数を書き写している箇所が無いか
  (`web/test/skillchain-bonus.test.js` にも `convertAugmentJaToEn` の
  重複定義があり、`web/js/utils.js` の実装とは別物になっている)

## 教訓

テストが実装の定義をコピーして持つと、コピー元が動いたときに一緒に動かない。
定数を検証したい場合は実装から読むか、実装を呼ぶ関数を検証する。
「ミラー」「〜と同じ値を持つ」といったコメントは、この問題の兆候として扱える。
